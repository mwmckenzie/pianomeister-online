# PianoMeister Online — Design Brief

## Vision

A browser-based piano practice visualizer: MIDI songs scroll down a perspective note highway toward a full 88-key keyboard, with built-in piano sound (or MIDI out), and practice tools built around bars, tempo, and per-hand control. Redesign of the Unity practice app (MarkovMusicMaker), not a port. Ships as a static site on GitHub Pages; runs on desktop and tablet.

## Scope — v1

**In**

- Song library: bundled songs + user uploads (drag-and-drop / file picker), uploads persisted locally.
- Perspective note highway receding to a horizon (Guitar Hero / Rocksmith style), all 88 keys by default (closer camera settings may crop the outer keys).
- Per-pitch-class note colors (repeating each octave), sustain bars, note highlight while sounding, 3D keyboard keys lit in the note's color.
- Sound: built-in sampled piano (default, all devices); MIDI out where the browser supports Web MIDI.
- Hands: channel 0 = right, channel 1 = left by default; user can reassign channels per song.
- Practice controls:
  - Play / pause.
  - Tempo as % of the song's baseline (applies across tempo changes); display effective BPM.
  - Bar-based seek: next bar, previous bar, go to bar #.
  - Bar-based A–B loop: `1–3` = start of bar 1 to end of bar 3.
  - Pre-roll beats before start and before each loop iteration, played muted or at reduced volume (default 0).
  - Per-hand mute / solo (audio), independent of visibility.
- Profiles (local), with:
  - Bookmarks: a saved practice setup = A–B section, tempo, mute/solo, pre-roll (channel assignments stay per song per profile, decision 67).
  - Session stats: total sessions, songs practiced, total practice time, most practiced song, last practice, average session length, …
  - Song stats: plays, total play time, bookmark count, …
  - Bookmark stats: plays, total play time, last played, …

**Out (for now)**

- MIDI input / play-along / scoring — but the architecture keeps a seam for it.
- Accounts, servers, cloud sync.
- Song editing.

## Key technical decisions

| Concern        | Decision                                                                                                                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| App shell / UI | Vite + Vue 3 + TypeScript, Pinia                                                                                                                                                                                           |
| Rendering      | Plain Three.js in an isolated `engine/` module (not TresJS); instanced note meshes; 3D keyboard in the same scene so lanes align with keys                                                                                 |
| MIDI parsing   | `@tonejs/midi` → converted into our own Song model                                                                                                                                                                         |
| Timing         | Own transport/scheduler on the Web Audio clock. Audio clock is master; visuals read song position each frame. Tempo % scales song-time advance.                                                                            |
| Bars           | Bar map built from the file's time-signature + tempo events (default 4/4 if none), unless the song has a per-song meter override, which replaces the file's time signatures. All seek/loop/pre-roll math is in bars/beats. |
| Sound          | `smplr` sampled grand, samples self-hosted in the repo; fewer velocity layers on mobile                                                                                                                                    |
| MIDI out       | Web MIDI via WEBMIDI.js, feature-detected (absent on iPad/Safari)                                                                                                                                                          |
| Storage        | IndexedDB via Dexie (uploads, profiles, bookmarks, play log); schema versioned from day one                                                                                                                                |
| Song identity  | Content hash of the MIDI file — stats and bookmarks survive renames and re-uploads                                                                                                                                         |
| Stats          | Store a raw play log; compute stats from it rather than maintaining counters                                                                                                                                               |
| Deploy         | GitHub Actions → GitHub Pages; Vitest + Playwright in CI                                                                                                                                                                   |

## Architecture outline

```
src/
  core/      pure TS, no DOM — song model, MIDI import, bar map, transport,
             practice config, stats calculations. Fully unit-tested.
  audio/     sampler output, MIDI out, output routing (per-hand mute/solo)
  engine/    Three.js scene: highway, notes, keyboard, camera; reads transport time
  data/      Dexie database, repositories (songs, profiles, bookmarks, play log)
  ui/        Vue components + Pinia stores (library, player HUD, settings, stats)
```

The transport emits note-on/note-off events on a small event bus; audio, MIDI out, and the visual key highlights all subscribe. Future MIDI input becomes one more participant on that bus.

### Core data model (sketch)

- **Song**: `id` (hash), title, source (bundled | uploaded), channels present, duration, bar map.
- **SongMeta**: songId, display title, composer, tags — user edits, shared across profiles.
- **StoredUpload**: songId, file name, bytes, addedAt, original title and composer (guessed, decision 79).
- **PracticeConfig**: loop `{startBar, endBar} | null`, tempoPercent, per-hand audio (on / muted / solo), preRollBeats, preRollMode (muted | quiet). No channel assignments (decision 67).
- **MeterOverride**: time signature, bar-1 start tick (per song, shared across profiles).
- **PedalInterval**: channel, startTick, endTick (sustain pedal CC64 down at value ≥ 64).
- **Profile**: id, name, colour, createdAt. Per-song channel assignments are stored per profile; settings are device-wide (decision 23).
- **Bookmark**: id, profileId, songId, name, autoName (decision 76), PracticeConfig (incl. metronome mode, decision 61), createdAt, updatedAt. "Full song" (`full:<songId>`) is a virtual bookmark for stats.
- **Session**: id, profileId, startedAt, endedAt (the last playback).
- **PlayRecord**: id, profileId, sessionId, songId, bookmarkId (what the setup matched exactly: a bookmark id, `full:<songId>`, or null for other setups), startedAt, playedMs, plays (starts, decision 70), and the setup it was played with (tempoPercent, loop or null, handAudio right/left, preRollBeats, preRollMode, metronomeMode) — one per playback stretch, split when the setup or what it matches changes. Records from before milestone 7.6 may also carry `temporary`.

## Confirmed decisions

1. **Unassigned channels** (neither hand) are hidden and silent.
2. **Pre-roll** shows the preceding bars' notes on the highway while their sound is muted or quieted; when there is nothing before the start (e.g. bar 1), the highway runs empty for the pre-roll. **Optional metronome click** during pre-roll.
3. **Per-song meter override**: MIDI files can carry wrong or missing time signatures, leading silence, or a pickup (anacrusis). Each song can override its meter with a time signature (replacing the file's) plus the tick where bar 1 starts; anything before that tick forms bar 0 (a pickup or lead-in). All bar-based features (seek, A–B loops, bookmarks, pre-roll) use the overridden bar map.
4. **Profiles are local to the browser/device**, with JSON export/import for backup and moving between devices.
5. **Session** = starts on first playback, ends after 10 minutes without playback or when the app closes. Practice time counts only while playing (not paused).
6. **Songs are shared** across profiles on a device (with their metadata edits and meter overrides); bookmarks, the play log and sessions, per-song channel assignments and the last opened song/bookmark are per profile. Settings are device-wide (decision 23).
7. **Tablet readability** of 88 lanes: deferred — not a primary concern for v1.
8. **Stop and song end:** stop rewinds to the loop's start bar if a loop is set, otherwise to the song start (bar 0 if there is a pickup). A stopped transport is parked there. **Every committed loop change moves the playhead to the new loop start:** turning the loop on, setting a range (Set loop, the range slider when released — not while dragging; with arrow keys once ~400 ms pass without another step, or at once when the thumb loses focus — or a committed From/To field), Revert to bookmark, and loading a bookmark. While playing it seeks there and plays the pre-roll; while paused or stopped it parks there. Overview loop-handle drags (on release), **Loop these bars**, and a loop editor range edit of the loaded bookmark (decision 107) are committed loop changes too. Turning the loop off leaves the playhead where it is. The Stop button and `Home` both stop and rewind like this. Reaching the last note-off with no loop silences all notes and stops (rewound).
9. **Jumps play onsets only:** after a seek or loop wrap, notes already held at the target are not retriggered; only notes starting from there on sound.
10. **Pre-roll triggers:** play from stopped, any seek (including a seek while paused, which applies on the next play), and each loop iteration. Resuming from pause without a seek does not re-apply pre-roll. Pre-roll beats are spaced at the tempo and meter of the target bar.
11. **Piano samples are self-hosted** in the repo (Splendid Grand Piano, public domain, via smplr), credited in `docs/CREDITS.md`. No runtime dependency on third-party sample servers.
12. **Sustain pedal (CC64)** is honored in the **sound only**: a note released while its channel's pedal is down keeps sounding until the pedal is released (re-striking the same pitch cuts the previous one). Highway bars still show written lengths.
13. **Pedal shading:** periods with the pedal down are shown as a subtle, desaturated band underneath the full width of the note highway — low-contrast so it doesn't compete with the notes. Rendering is milestone 3; the data comes from milestone 2. **From milestone 9** the band is the **pedal cage** (decision 116): full width while the pedal is down, with its own border and fill options; this look stays the default style.
14. **Volume controls:** master volume; per hand a volume slider plus on / muted / solo (if any hand is soloed, only soloed hands sound). Audio only — never affects visibility.
15. **Pre-roll "quiet" level** defaults to 25% of normal volume.
16. **Metronome:** synthesized click (no sound files), accented on beat 1. Modes: off / pre-roll only / always. Own volume slider.
17. **Data model:** `PedalInterval` — channel, startTick, endTick (down at value ≥ 64).
18. **Highway geometry:** look-ahead measured in quarter notes (ticks / ppq), default **8**, adjustable. The visible highway — from the now line to where the top of the screen meets the highway — corresponds to **1.5×** the look-ahead: the look-ahead fills the lower two thirds, and notes fade in through a haze in the top third (1×–1.5×), so nothing pops in at the screen edge. Spacing is tempo-independent: slowing the tempo slows the scroll, not the spacing.
19. **Notes:** flat strips. **Head** = solid pitch color, length of a **1/64 note** (ppq/16 ticks), or the whole note if shorter. **Sustain** = the rest of the note, full lane width, translucent with a gradient **across the lane**: **25% transparent at the lane center, 75% at the lane edges** (both adjustable). The gradient is computed in each note's own lane coordinates, so it follows the note's perspective and taper — it is never screen-aligned. **From milestone 9:** heads and sustains each have a fill style (decision 112); for sustains **Solid** is this gradient, and the centre/edge transparencies apply to every sustain style.
20. **Keyboard proportions (grand piano):** white key 23.5 mm wide × 150 mm visible length; black key 13.7 mm × 95 mm, slightly raised. World unit = one white-key width. Key proportions are fixed in world space and never change with camera settings.
21. **Camera:** tilt default **45°** (adjustable); **distance offset**: 0 = all 88 keys exactly fill the screen width, positive = farther away, **negative = closer, cropping the outer keys**; **horizontal pan**, default centered. The keyboard and the highway share the camera, so lanes always meet their keys.
22. **Scene defaults (all adjustable):** background very dark blue (`#05070F`), highway surface slightly lighter (`#0A0F1E`); lane lines desaturated blue, translucent; bar lines the same hue, clearly more visible; beat lines barely visible; pedal band subtle desaturated blue-grey. **Milestone 9** darkens these further (provisional values until its tuning session, decision 108) and adds an optional vignette and the line styles of decision 111.
23. **Settings** are stored in localStorage (versioned) and are **device-wide**: all profiles share them (milestone 7 keeps it that way).
24. **Home and routes:** the player is `#/`; **Welcome** (`#/welcome`, decision 93) is the start screen, shown over the player's paused scene; the stats page is `#/stats` (decision 97); the **loop editor** is `#/editor` (decision 106), shown over the player like Welcome; the debug page stays at `#/debug`. Appearance → Start → **Start on**: Welcome (default) or Player decides where the app opens when started at the site root (no hash: a bookmark or the home-screen icon); an explicit `#/` link, or reloading the player, stays on the player.
25. **HUD:** replaced in milestone 6 by the Quiet HUD (decision 60). Milestone 3 layout, for reference: top-left song title, length, position, bar:beat; top-right current and song BPM and tempo %; temporary top-center controls; a gear button for the settings panel.
26. **Library page** at `#/library`: searchable, sortable list; group by composer or tag; filter by tag and source. Picking a song opens it in the player; the player has a Library button.
27. **Startup:** the player reopens the active profile's last opened song or bookmark and parks it where playback last stopped (decision 94); with Start on = Welcome that happens behind Welcome, so Resume is instant. First run falls back to the first bundled song.
28. **Song metadata is editable for every song** (bundled and uploaded): display title, composer, free-form tags. Edits are stored locally and shared across profiles; the original values are kept and can be restored ("Reset to original").
29. **Uploads:** multiple files at once; `.mid`/`.midi` only; max 2 MB each; duplicates detected by content hash (against bundled songs and other uploads) are skipped with a message; uploads can be deleted (with confirmation). Bundled songs can't be deleted.
30. **Hand channel fallback:** if neither channel 0 nor 1 has notes, assign by average pitch — highest-average channel → right hand, next → left, others hidden; a single channel → right hand. Users can change it in the song's details panel.
31. **Song details panel** (inside the Library page): metadata and tags, file facts, hand channel assignment, meter override editor, delete (uploads only), Play.
32. **Library export/import:** one `.zip` containing all uploaded MIDI files plus a versioned `library.json` (metadata edits and tags for all songs, meter overrides). Importing skips duplicates; for songs already present, local metadata edits are kept and the import report says so. From milestone 7 the same backup also holds profiles and their bookmarks, hand assignments, sessions and play records (decision 75).
33. **Storage protection:** request persistent storage (`navigator.storage.persist()`) on the first upload and show the storage status in the Library; ship a web app manifest so the site can be added to an iPad/iPhone home screen (home-screen apps aren't subject to Safari's 7-day storage deletion). Offline support (service worker) stays in milestone 11.
34. **Adding bundled songs:** drop the `.mid` into `public/songs/`, run `npm run songs:manifest`, then fill in title/composer/tags in the manifest.
35. **Deleting an upload** also deletes its metadata edits, meter override and hand assignments (all profiles). The confirm dialog asks whether to also delete its bookmarks and practice stats, default **keep**: they are keyed by the content hash and come back if the file is uploaded again (decision 74).
36. **Original title and composer of an upload:** guessed from the file when it is uploaded (decision 79); "Reset to original" returns to that guess. Uploads have no original tags. Uploads stored before milestone 7's review round 3 keep the title they had (no silent renames) and an empty original composer; **Guess from file** guesses again on request.
37. **Library export** holds metadata edits and meter overrides; from milestone 7 it also holds every profile with its hand assignments, bookmarks, sessions and play records — one backup file for everything (decision 75).
38. **Playback survives navigation:** the app keeps one playback session, so going to the Library and back doesn't reload the piano samples. Leaving the player — for the Library, Stats, or Welcome (which keeps the scene, paused, as its backdrop) — pauses playback and remembers the bar where it stopped (decision 94). The **loop editor** is the exception: playback keeps running while you edit (decision 107).
39. **3D note heads:** heads are raised blocks with the head's footprint (lane width × 1/64 note), height **0.35**, **rounded edges on** (radius 0.06, at most 40% of the head's smallest side). The bevel keeps its world size whatever the note length, tempo or look-ahead. Sustains stay flat. Black-lane heads draw above white-lane heads. Fill styles and edge glow from milestone 9 (decisions 112–113): Glass heads stay depth-writing blocks (front faces only); Neon heads are a dark translucent body with a bright rim.
40. **Black-key-lane notes are lifted** (heads and sustains). Default: **match the black-key height**, so they meet the raised key tops at the now line; or a manual lift 0–0.8 (default 0.51).
41. **Contact shadow** under black-lane notes, falling on the highway and neighbouring white-lane notes: strength **45%**, soft edge. Faked with soft quads — no shadow maps.
42. **Black-key lane shading:** black-key lanes on the highway are darker than white-key lanes: **on**, strength **22%**.
43. **Simple lighting:** one key light + ambient, computed in the shaders, for keys and note heads: lighter top faces, darker sides, highlights on bevels. No shadow maps or post-processing (milestone 9). **Milestone 9** adds selective bloom (decision 109) and key light (decision 118).
44. **Keyboard dimensions** (defaults = real grand-piano proportions; "Reset to grand piano" restores them): key thickness (body height) **0.6**, gap between white keys **0.06**, black key length **63%** of white, black key height **12 mm (0.51)** above the white keys. Lanes never move: the gap shrinks white key bodies inside their lanes; black keys keep their lane width. **Limits** (in the settings and in the geometry): black key height ≤ key thickness, so a raised black key's body always reaches down to the white keys and never floats above them; black press depth ≤ black key height − 0.08 (≈2 mm), so a fully pressed black key's top stays above the white key tops (lowering the black keys lowers this limit and clamps the depth); white press depth ≤ key thickness, so a pressed white key's front never drops below the keyboard's bottom.
45. **Key edge profile:** none / chamfer / rounded, with a size. Default **chamfer, 0.04** (≈1 mm) on all edges of white and black keys.
46. **Animated keys:** keys go down on note-on and return on note-off (quick press ≈40 ms, slower release ≈90 ms, eased, no overshoot); a repeated note re-strikes from half-pressed. **On**. Separate settings for white and black keys: press depth = how far the key's **front edge** drops (white **0.22**, black **0.30**), and pivot offset = how far the pivot sits **behind** the key's visible back edge (white **0** — hinged at the play line; black **2 × the black key's visible length**, ≈8.04). Real keys pivot well behind their visible part (the balance rail), so they move mostly downward with a slight tilt; with the default black pivot a black key's back drops 2/3 as far as its front and stays on the play line (it moves a hair away from the player, never opening a gap). The colour overlay moves with the key.
47. **Velocity-scaled effects:** spark count and size and held-glow size scale linearly with velocity, **0.6×** at velocity 0 to **1.7×** at 127: **on**; or uniform size. From milestone 9 the same scaling applies to every now-line effect and to the note-on pulse.
48. **Render quality:** render scale **auto** (device pixel ratio) or 0.5×–2×, capped by max pixel ratio (default **2**); anti-aliasing off / MSAA / FXAA / SMAA (three's built-in passes), default **MSAA**. The drawing buffer follows device-pixel-ratio changes (zoom, moving between monitors). The settings show internal resolution and average frame time. **Milestone 9** adds the quality presets (decision 110), bloom (decision 109) and GPU time in the readout where the browser can measure it.
49. **Settings schema v2** with migration: stored v1 settings are kept and new keys get their defaults; settings from an unknown newer version fall back to defaults.
50. **Two homes for settings.** Settings that change what you see on the playfield (camera, keyboard, highway, notes, effects, render quality) live in the **playfield sidebar**, beside the live view (from milestone 9: the Look picker on top, then Camera, Keyboard, Highway, Lines & glow, Note style, Effects, Pedal & cages, Note names, Render quality). The sidebar's sections are an accordion: one open at a time (clicking the open one's header closes it; none open by default), the opened header scrolled to the top of the panel (instantly under reduced motion), the open section remembered across reloads as UI state; the Look picker stays above the sections, outside the scroll area. Everything else lives in the **settings window** with tabs: General, Practice, Audio, Appearance, MIDI, Profiles, Library & data, Shortcuts, About. Tabs with nothing to show yet are left out until they have content (milestone 6 shows Practice, Audio, Appearance, Library & data and About).
51. **Reset to default everywhere.** Every setting control has a reset button: a circular-arrow icon with a "Reset to default" tooltip (hover and keyboard focus), dim at the default and in the primary color when changed, never shifting the layout. Every section ends with "Reset ⟨section⟩"; every settings tab and the playfield sidebar end with "Reset all ⟨tab⟩ settings". Section and tab resets apply at once and show a toast with **Undo** for 6 seconds (no confirm dialogs); a new reset replaces a visible Undo toast, and Undo restores only the most recent reset. Tabs and sidebar sections with changed values show a small dot in the primary color.
52. **Menu colors.** Appearance has a **primary** color (buttons, sliders, selection, active tabs, focus rings) and a **secondary** color (charts, bar-range indicators, highlights), each with a color picker and hex value, plus presets: Glacier `#8AB4FF`/`#7EE0C3` (default), Aurora `#7EE0C3`/`#C3A6FF`, Ember `#FFB38A`/`#FFD98A`, Orchid `#D3A6FF`/`#8AB4FF`, Mono `#E8ECF6`/`#A7B0C6`. They affect the UI and, from milestone 9, may colour scene lines and cages (decision 111) — never the notes. Text on primary buttons is dark or light, whichever contrasts more.
53. **Glass panels:** panel opacity (default **58%**, 30–95%) and background blur (default **26 px**, 0–40). With blur 0, or where `backdrop-filter` is unsupported, panels use a more opaque surface.
54. **Motion:** menu animations "Follow system" (default, respects `prefers-reduced-motion`) / Full / Reduced. Reduced = fades only, no movement. From milestone 9 Reduced also covers the scene: no flicker, breathing, scrolling or noise animation, and now-line effects become short fades.
55. **Font:** Inter Tight, self-hosted woff2 (weights 300/400/500/600), credited in `docs/CREDITS.md` (OFL). No runtime Google Fonts request.
56. **Tempo shown as a range** wherever a song's tempo is displayed: the 5th to 95th percentile of the tempo, weighted by song time (seconds at each tempo), up to the song's end — so a short ritardando or pickup doesn't set the range. A single value when constant, e.g. "120–126 bpm" or "100 bpm". The library facts, the bundled manifest and the stored uploads all use the same function. Stored facts carry a `factsVersion` (`FACTS_VERSION`, bumped whenever the facts gain a field): on library load, uploads with older or missing facts are recomputed in the background one at a time and the lists update as each finishes; a file that can't be re-read keeps its old facts and isn't retried until the next version. The bundled manifest must be at the current version (`npm run songs:manifest:check`, and a unit test). The stored facts also hold each channel's note count and pitch range and the file's meter summary, so the picker shows notes per hand (with the song's hand assignment), the pitch range and meter changes without parsing the file. The player HUD keeps showing the current bpm.
57. **Song picker** opens from the player toolbar and with `O`. Left: song list. Middle: details of the highlighted song (until milestone 7's stats: notes per hand and the pitch range under the facts). Right: what to load — "Full song" pinned first, bookmarks below (milestone 7). The picker and the library share one song-row component and the reference grids: fixed-width numeric columns whose headers are the sort controls. Long titles and composers truncate with an ellipsis and show the full text as a tooltip. The library's details panel is always shown (first row selected by default); its backdrop is the player's last frame, blurred. A song's meter shows the meter covering the most bars, followed by a small superscript "+" in the secondary colour when it changes ("4/4+"). The "+" is a button named for the count ("4 meter changes"); hover (after a short delay), keyboard focus, or a click or tap opens a popover listing "bar X · meter", and leaving it, Esc, or a tap elsewhere closes it. Esc there never closes the dialog around it.
58. **Composer field** is a combo box: free typing with suggestions from composers already in the library (case-insensitive substring), a button that lists all of them with song counts, and "Add ‘…’ as a new composer" when nothing matches exactly.
59. **UI components:** Reka UI (headless, accessible primitives) for dialog, tabs, accordion, slider, combobox, select, tooltip, toggle group, popover and toast, styled with our own design tokens (`src/ui/theme/tokens.css`). No styled component framework. Settings are declared once in a registry in `core/settings` (label, default, limits, unit, home); reset groups are derived from it.
60. **Quiet HUD, on the sides of the highway** (nothing over it; no panels, pills or scrims behind any HUD element — text shadows keep it readable). **Top edge:** a thin full-width timeline (28 px side margins) with bar ticks, progress in the primary color with a soft playhead glow, the loop region tinted with the secondary color and its first and last bar numbers below; it seeks to bar starts and never hides. A chevron at its right end opens the **overview strip** (decision 105, `V`), which sits directly under the timeline, between the left and right columns (about 24 px from each, following their measured widths, the window size and the playfield panel); the columns stay exactly where they are, and while the strip is open the title, composer and now-playing line truncate at its left edge (full text as a tooltip). At narrow widths the strip gets narrower; with less than about 360 px between the columns it isn't shown — the chevron's hint reads "Not enough room for the overview here · open the loop editor (E)" and the chevron or `V` opens the loop editor instead — and it comes back by itself when there's room. **Left column:** song title, composer, then the **now-playing line** on its own line, same size, weight and text shadow (decision 69): when the setup matches a bookmark or Full song exactly, a bookmark icon sized to the text and its name ("Full song" for Full song), both in the secondary colour like the loop region; otherwise the setup itself in the dim neutral text colour, written like an automatic bookmark name ("Bars 20–35 · 100% · both hands · quiet pre-roll 2"; "Full song · 85% · left muted · pre-roll 2" without a loop), whose hover hint reads "Doesn't match a bookmark · press ⟨key⟩ to save it" (the key in effect for Save as bookmark); the "bar 18:2 beat" counter and "bar N of M"; then the app menu as a vertical column of icons (36 px apart) — Home (`H`, lit on Welcome), Change song (`O`), Loop editor (`E`, a piano-roll strip with a selected section; lit while the editor is open; it opens the editor from Welcome too), Library (`L`), Stats (`S`), Playfield panel (`P`), Settings (`,`), Keyboard shortcuts (`?`), and the profile item with two or more profiles (decision 66). The menu is at its height limit: at 1280×720 with two profiles (nine items) it ends just above the keyboard, so a further item needs the menu to move up or reflow (e.g. two columns), not tighter spacing. They are grey and dim at rest; on hover or focus they turn white and show their name and shortcut as plain text beside them; the playfield icon is primary while the panel is open. **Right column**, right-aligned: the current "107 bpm" (information only, not clickable), "85% of 126 bpm" (the percentage in primary when not 100%), the time "0:52 / 1:31"; then the transport (stop, previous bar, play/pause, next bar), and one line per toggle with its value as colored text left of its icon: "bars 17–32", the loop-options caret and the loop icon (secondary when on); "85%" and the tempo icon (primary when not 100%; it opens the tempo popover, 25–200%); the metronome icon (primary when on, "pre-roll" beside it in pre-roll mode; `M` toggles between off and the last mode that wasn't off, default always; while a bookmark was the last thing loaded the change is temporary, with Full song it edits the Audio setting); then the save-bookmark icon (decision 77; dim like the others, its hover hint "Save as bookmark B"). Off = a dim grey icon with no value. The loop popover has a two-thumb bar range kept in sync with from/to fields (start ≤ end, a one-bar loop allowed; the dragged or focused end pushes the other, for pointer and keys alike), pre-roll beats on an inverted slider reading "4 beats before bar 17" ("4 beats before the play position" without a loop), "Back to start" and "Save as bookmark". **Bar:beat counter:** bar and beat sit in fixed-width digit slots measured in the big font's `ch` (the bar slot fits the song's highest bar number, right-aligned; the beat slot its largest beat count), with a tight colon and fixed 8 px gaps to "bar" and "beat", so nothing shifts as the numbers change. To its right a vertical stack of beat dots, beat 1 at the bottom filling upward like the highway: the current beat primary with a soft glow, beats already played in the bar faintly lit, reset on each downbeat; bars of 6 or more beats split into columns by pulse (6/8 = two columns of three). During a count-in the counter never shows bar 0 or negative bars: it shows the target bar and beat 1 (e.g. "17:1") dimmed to about 45%, and the dots count the pre-roll beats; from the target bar's downbeat it is back to normal. Default shortcuts (all rebindable in Settings → Shortcuts, decisions 80 and 83–89): Space, ←/→, `Home` (stop: back to start), `-` / `+` (or `=`) / `0` (tempo down, up, 100%), `B` (save as bookmark), `M` (metronome), `O`, `L`, `P`, `,`, `?` (shortcuts), `H` (Home), `S` (Stats); the menu hints and the transport tooltips show the keys in effect; they are ignored while typing in a text field, combo box or editable area.
61. **Audio and practice settings are persisted** (master volume, per-hand volume and on/mute/solo, quiet pre-roll level, metronome mode and volume, pre-roll beats and mode). They are what "Full song" uses. From milestone 7 a bookmark may override **only** per-hand mute/solo, pre-roll beats and mode, tempo, and the **metronome mode** (off / pre-roll / always); master volume, hand volume levels and the metronome volume stay global. The Practice tab also holds the **tempo step** (decision 81).
62. **Keyboard lengths are shown in mm** (world units × 23.5), e.g. black key height 12 mm; they are stored in world units.
63. **Settings schema v3** adds the audio, practice and appearance sections; v1 and v2 settings are migrated (values kept, new keys get defaults). The playfield panel's open state is UI state, stored separately (`pianomeister.ui`), and has no reset.
64. **Controls hide when idle:** while playing, the app menu icons and the right-hand playback block (transport and toggles) fade out after a few seconds without pointer, keyboard or touch activity; any activity brings them back. The timeline and all information text (title, counter, bpm, time) always stay; so do the overview strip's notes, bookmark lane, loop and playhead, while its header controls fade with the menu. They never hide while paused, while a popover or dialog is open, while a playfield-panel control has focus, or while the pointer is over them. Appearance → Player controls → "Hide controls when idle": a switch (default on) plus "After", 0.5–10 s in 0.5 s steps (default 3 s), disabled while the switch is off; each has its reset icon. Settings stored as Off / 2 / 3 / 5 / 10 s migrate to switch off, or on after that many seconds.
65. **Profiles** are local to the browser (decision 4). Each has a name and a colour (one of the five preset primaries, decision 52). First run creates one profile, "Me" (id `default`), silently; with a single profile nothing about profiles shows in the player. Settings → **Profiles** lists each profile with its colour, name, total practice time and last practiced, and can create, rename, recolour, switch and delete (a confirm names what is deleted: its bookmarks and stats; the last profile can't be deleted). The tab also shows the active profile's summary stats, with a "See all stats" link to the stats page.
66. **Profile switching:** with two or more profiles the player's left menu gains a fifth item at the bottom — a small circle in the profile colour with its initial, dim at rest like the other icons — that opens a compact switcher popover (no shortcut). Welcome's profile chip opens the same switcher (or Settings → Profiles with one profile). Switching stops playback, reopens that profile's last song or bookmark, and shows "Switched to ⟨name⟩".
67. **Bookmarks** store a name, the song, a bar range (start ≤ end), tempo %, per-hand mode (on / muted / solo), pre-roll beats and pre-roll mode, and the metronome mode (off / pre-roll / always) — the overrides decision 61 allows. Not hand-channel assignments (per song per profile) and not volumes, the metronome's included (global). Bookmarks stored before the metronome mode existed have it off. A bar range beyond the song's last bar (after a meter override) is clamped on load and in lists, never rewritten; the manager says so.
68. **"Full song"** is tracked like a bookmark for stats (id `full:<songId>`), but only while the setup matches it exactly: no loop, 100%, and hand modes, pre-roll beats and mode and metronome mode equal to the global settings (Audio and Practice tabs); the now-playing line then shows it with the bookmark icon (decision 60). It always exists, can't be edited, renamed or deleted, and loads with no overrides — whole song, tempo 100%, hands and the metronome mode from the Audio settings, pre-roll from the Practice settings. It comes first in the picker's Load list; the bookmark manager doesn't list it (only real bookmarks). The Practice tab's pre-roll rows always edit these global defaults, also while a bookmark is loaded; then a note says so ("The defaults for Full song. ⟨bookmark⟩ has its own pre-roll · edit it in the Bookmark manager").
69. **Loading, temporary changes and what's playing:** loading a bookmark applies its loop (on), tempo, hand modes, pre-roll and metronome mode. **Bookmarks are edited only in the bookmark manager and the loop editor (decision 107), never from the player screen.** The last loaded entry (a bookmark, or Full song) stays the session layer: while a bookmark was the last thing loaded, player-side changes (loop range, tempo, pre-roll in the loop popover, hand On/Mute/Solo and the metronome mode in the Audio tab) are temporary — they apply at once but never write to the bookmark or to the global settings, are dropped when another song or bookmark loads, and those controls' reset icons go back to the bookmark's saved value; with Full song loaded they edit the global settings (loop and tempo are session state). **What's playing** is decided live from the setup, not from what was loaded (`nowPlaying`): the bookmark of the song whose settings it matches exactly (decision 78, the range clamped as on load), else Full song if it matches that (decision 68), else a custom setup. Changing settings so they match another bookmark **adopts** it: the now-playing line shows it and it gets the plays and time from then on — no jump, no reload, no toast — while the last loaded entry stays what Back to returns to, what decides temporary vs. global edits, and what Resume reopens. There is no temporary-changes dot and no "Temporary for …" note; the line itself says what's playing. While the setup differs from the last loaded entry, the loop popover offers **Back to ⟨name⟩** ("Back to Full song": loop off, 100%), which drops the changes (a loop that changes jumps to its start, decision 8). **Save as bookmark** (decision 77) only ever creates a new bookmark. The bookmark manager doesn't create bookmarks; it duplicates them (decision 78), and deleting shows the Undo toast instead of a confirm; a deleted bookmark's play records are kept and still count for its song.
70. **Practice time and plays:** practice time is time the transport is playing (decision 5), pre-roll included. A **play is a start**, not a finish: one play when playback starts after loading a song or bookmark, after Stop / Back to start / the song ending (a timeline click before Play changes nothing), at every loop wrap, and at every committed loop change's jump to the new loop start (it restarts a section: while playing it counts at once, while paused or stopped the next Play counts; loop nudges settle first, so one jump is one play). Resuming after a pause is not a play, wherever the playhead was moved meanwhile. **Attribution:** every play and every second counts for the song; a bookmark or Full song gets them only while the setup matches it exactly (decision 69); anything else is recorded for the song with no bookmark ("other setups"). The raw log has one `PlayRecord` per playback stretch (start → pause, stop, song end, load, tab hidden), rewritten every 30 s while playing so a crash loses at most 30 s, and on each play counted. Each record keeps the full setup it was played with — tempo %, loop range (null = whole song), right and left hand modes, pre-roll beats and mode, metronome mode — and what it matched (bookmark id, `full:<songId>`, or null); a change of either mid-stretch ends the record and starts a new one. Records from before milestone 7.6 counted complete passes; those count as plays, with the attribution they were recorded with. Sessions follow decision 5 (a new session after 10 minutes without playback; its end is the last playback). Stats are always computed from the log, never stored as counters.
71. **Stats shown** (per active profile): per song — plays, practice time, last practiced and the 14-day chart from **all** of the song's records (its bookmarks, Full song, other setups, and bookmarks since deleted), never summed from bookmarks, so editing or deleting bookmarks never changes a song's totals; bookmark count. Per bookmark and Full song — plays, practice time, last practiced (only records that matched it) and its share of the song's practice time (the song's total, other setups included); per song also "other setups" (plays and time on setups that matched nothing). A 14-day chart of practice minutes per local calendar day (today in the primary colour); the profile summary — sessions, songs practiced, total practice time, most practiced song, last practice, average session length. Formats: "14 min", "1 h 5 min", "—" for none; last practiced "Today", "Yesterday", "4 days", "10 Nov".
72. **Song picker with practice data:** the song list shows title + composer, bookmarks, plays, time and last (headers sort; click again to flip), sorted by last practiced by default. The middle shows the facts, then the song's stats and chart, then the selected entry's stats ("Bars 17–32 · 85% · left muted · pre-roll 2", Played, Practice, Share) and chart, and under them "Other setups: 12 plays · 18 min" when the song has any (decision 71). The Load list pins Full song first, then the song's bookmarks with their range bar, plays, time and last. The footer button reads "Load full song" or "Load bookmark".
73. **Library practice columns:** Title, Composer, Length, Plays (starts, decision 70), Last, Added — all sortable by header (no separate sort menu); Bars is shown in the details panel and the picker. Below about 1100 px Added is hidden too. A song's row subtitle is its bookmark count ("2 bookmarks"). The page header has **Library | Bookmarks** tabs; the details panel has a **Bookmarks** button that opens the bookmark manager (`#/bookmarks`) filtered to the song.
74. **Deleting an upload** asks whether to also delete its bookmarks and stats, default **keep**; the confirm scrolls into view in the details panel as it opens (smoothly unless motion is reduced). Bookmarks of songs that are missing are hidden from lists, not deleted.
75. **Backup with profiles:** the library backup (decision 32, format 1.2; 1.0 and 1.1 still import — a 1.1 record's complete passes count as plays) also holds profiles, bookmarks, hand assignments, sessions and play records. Import adds what is missing by id and never overwrites. A backup profile whose id matches a local profile (typically both "Me") is never merged silently: one dialog step per colliding profile ("1 of 2") shows both sides (bookmarks, practice time, last practiced) and offers **Merge** (adds the backup's missing bookmarks and history; nothing local changes), **Add as a new profile** (named "⟨name⟩ (imported)", with new ids) or **Replace** (deletes the local profile's bookmarks and history, then uses the backup's; warns and offers "Export current data first"). The default is Merge when the names match and Add as new when they differ. Profiles without a collision are added without asking. Cancel import writes nothing; the summary toast says what happened ("Imported: merged into Me (+5 bookmarks), added 1 new profile.").

76. **Bookmark names:** a new bookmark is named automatically with its full summary, every part named — "Bars 1–4 · 100% · both hands · pre-roll 2" ("no pre-roll" at 0; "quiet pre-roll 2" when the pre-roll sound is quiet, muted staying implicit), plus "· metronome" or "· metronome in pre-roll" when the metronome isn't off. Each bookmark stores `autoName`: while true, the name follows the bookmark's settings whenever they change in the manager; typing a name sets it false; the name field's reset icon makes it automatic again. Lists show the summary under a name only when the name is custom. Bookmarks named with milestone 7's earlier "Bars X–Y" pattern became automatic (database v4; backups import the same way).
77. **Creating bookmarks** happens in the player (and from an overview selection in the strip or the loop editor, decision 103), in one click with no dialog: the save-bookmark icon in the right column (`B`), or **Save as bookmark** in the loop popover. It saves the song, the loop range (the whole song with no loop), tempo, hand modes and pre-roll with the automatic name, makes it the loaded bookmark (nothing audible changes; the setup now matches it, so the now-playing line shows it and nothing restarts) and shows "Saved "⟨name⟩"" with **Rename** (opens the manager with the name focused) and **Undo** (removes it and puts back what was loaded, temporary changes included).
78. **No exact duplicates:** two bookmarks have the same settings when song, range, tempo, right and left hand modes, pre-roll beats and mode, and metronome mode are equal (the name doesn't count). Saving settings the profile already has creates nothing: that bookmark is loaded (temporary changes dropped) and the toast says "Already saved as "⟨name⟩" · no new bookmark created" with **Show**. In the manager, **Duplicate** makes a draft that lives only in memory, selected and focused, with the note "Duplicate of "⟨name⟩" · change something to keep it"; the first edit that makes it differ from every bookmark saves it (auto-named). Leaving a draft that is still identical (another bookmark, a song filter, Load in player, another tab or route) asks "Discard this duplicate?" — "It has the same settings as "⟨name⟩", so it won't be kept unless you change something." — with **Keep editing** (default) and **Discard duplicate** (drops it and carries on; from Load in player it loads the bookmark it matches); a reload drops it silently. An edit that makes a bookmark the same as another shows "Same settings as "⟨name⟩"" (saved anyway; a draft stays a draft).
79. **Guessing an upload's title and composer** (and a new bundled file's, in `npm run songs:manifest`). Title: the sequence (first track) name unless generic ("Track 1", "Piano", "untitled", empty…), else the file name cleaned up — no extension, `_`/`-` as spaces, no "TwoHands"/"FourHands" or "(c)name" suffix, "bwv 779" → "BWV 779", "No10" → "No. 10", single spaces — with a composer's name dropped from its start or end. Composer: "Composer: X" / "by X" in a text event (not "Sequenced by"); else a composer named in the texts, sequence name or file name — first one already in the library (by surname, keeping its spelling), then a built-in list of well-known composers with aliases and catalogue prefixes (Bach, BWV → J. S. Bach; Beethoven → Ludwig van Beethoven…); else the copyright holder ("© 1999 Jane Doe"); else empty. Copyright comes last because it usually names whoever sequenced the file.
80. **Keyboard commands live in one registry** (`src/core/commands/COMMANDS.ts`): each has an id, a label, a one-line description, up to two default keys (decision 87) and a scope (decision 86). All key handling and every key hint read the keys in effect (defaults plus the user's overrides, decision 88); shortcuts stay ignored while typing (decision 60), while a dialog has the keyboard, and while a key is being recorded. Keys that belong to a focused control by its role (sliders and the timeline, text fields, tag and combo boxes) stay with the control and aren't commands. No default key conflicts under the scope rules (unit-tested).
81. **Tempo step:** Practice → Tempo → "Tempo step", 1–10 % in whole percent (default 5 %), with its reset icon. The tempo popover's slider and its arrow keys (and the bookmark manager's tempo slider) move by it. The slider's grid is anchored at 100 %, so 100 % is always reachable; its ends are the furthest steps inside 25–200 % (e.g. 28–200 % for a 4 % step).
82. **After an upload or drop** the library selects the first new song (its details in the panel), scrolls it into view (centred when possible) and gives the row a short highlight pulse in the secondary colour (about 1.2 s; a colour fade only under reduced motion). Every song added while on the page carries a small secondary "New" tag until the library is left. If the search, source filter or tag filter would hide the selected song, that filter is cleared. A file already in the library selects and pulses the existing song instead. One toast says what happened: "Added "⟨title⟩"", "3 songs added", "Already in your library: ⟨title⟩", "2 added · 1 already in your library", plus "· N rejected" and "· filters cleared to show it" when they apply; the notice under the list still gives the rejection reasons.
83. **Settings → Shortcuts** lists every command grouped by scope — Player, Lists (song picker, library, bookmark manager; with the list role table, decision 90), Tabs, Everywhere (player, library and bookmark manager), Dialogs — each row with its key chips, "+" for another key and the reset icon (dim at default, primary when changed). The footer reads "N shortcuts changed from default" with "Reset all shortcuts" (Undo toast), and the tab gets the changed dot. "Close" (Esc) is listed but fixed. The help text says letters follow the layout, that Shift+letter isn't a separate shortcut while Ctrl and Alt combos are, and that focused sliders, the timeline, the overview and text fields keep their own keys.
84. **Recording a key:** click a chip (or "+") and it reads "Press a key… · Esc to cancel"; the next key press with any Ctrl / Alt / Shift / Meta becomes the binding. A modifier alone doesn't count; leaving the chip stops recording; Esc cancels without closing the settings window. Up to two keys per command; × (on hover or focus) removes one; a command may have none ("—", mouse only).
85. **Reserved keys** can't be recorded; the row says why for a moment: "Esc is reserved for closing", "Tab moves focus", "Ctrl+W is used by the browser". Reserved: Esc, Tab and Shift+Tab, Ctrl/Meta + W, T, N, Q, R, L, Tab, F4, Alt+F4, and F5, F11, F12 (`reservedReason` in core).
86. **Scopes and conflicts:** a key may be used once per scope. Player never runs at the same time as Lists or Tabs; Lists and Tabs run on the same pages, so they conflict with each other; Dialogs run on top of everything, and Everywhere keys work on every page, so those two conflict with every scope. Tabs (Next / Previous tab) work on the Library and Bookmarks pages, in the song picker and in the settings window. Recording a key another command uses shows "Already used by ⟨command⟩" with **Replace** (the key moves here; the other command loses it) and **Cancel**; nothing changes until one is chosen.
87. **Layout-aware keys:** a printable character without Ctrl, Alt or Meta is matched by the character it types (`KeyboardEvent.key`, case-insensitive, Shift folded in), so `?`, `,`, `-` and `+` work wherever they are on the user's layout (e.g. German QWERTZ). Everything else — Space, arrows, Home/End, Page keys, F-keys, Enter, and every combo with Ctrl, Alt or Meta (AltGr counts as Ctrl+Alt) — is matched by the physical key (`KeyboardEvent.code`). A Ctrl+Alt press that types a printable character (AltGr on Windows and Linux: `[`, `]`, `{`, `}`, `@` on German) also matches the character bindings when no physical-key combo claims it, so a Ctrl+Alt combo the user recorded comes first. Meta is written ⌘ on macOS and iPadOS, "Win" on Windows and "Meta" elsewhere (read once from `navigator.userAgentData.platform`, else `navigator.platform`); Ctrl stays "Ctrl". Labels everywhere read "Space", "←", "Home", "Ctrl+Shift+K", "?", naming physical keys by what they type on the user's layout where the browser tells us (`navigator.keyboard.getLayoutMap()`, Chromium), else on a US layout.
88. **Storing shortcuts:** device-wide like the settings and stored with them (settings v5: `{ version, settings, shortcuts }`), as overrides only (`{ commandId: Binding[] }`; absent = the defaults, empty = no key). Not part of the library backup. `Binding` is a tagged union (`{ kind: 'key', … }`) so milestone 11 can add `{ kind: 'midi', … }` for pedals and foot switches.
89. **New commands and the cheat sheet:** Tempo down / up by the tempo step [`-` / `+`, `=`] and Tempo to 100% [`0`] (like the tempo slider: temporary while a bookmark was the last thing loaded; like every command, they just change the setup, and the now-playing line and attribution follow), Loop on/off and **Back to bookmark** [no key; the loop popover's "Back to ⟨name⟩", for Full song too; nothing when the setup already matches the last loaded entry], and **Show shortcuts** [`?`], **Home** [`H`] and **Stats** [`S`] (Everywhere: Welcome, player, library, bookmark manager and stats; not while typing or another dialog is open); Show shortcuts and also opens from the left menu and the Shortcuts tab. The cheat sheet lists every command with its keys, grouped by scope, with "Change shortcuts…" (opens Settings → Shortcuts, going to the player if needed); Esc or its own key closes it. The cheat sheet also shows the list role table (decision 90).
90. **List roles:** on each page with lists, the **main list** is the one you choose from (it drives the details panel and Enter); the **side list** filters or refines it. Song picker: songs / the Load list (Full song and bookmarks), Enter loads the selected Load-list entry. Library: songs / the filter column (All songs — no source or tag filter — then the sources, then the tags), Enter plays. Bookmark manager: bookmarks / the song filter, Enter loads the bookmark in the player. Next / Previous in list (↑/↓) always move the main list, Next / Previous in side list (Shift+↑/↓, physical keys) the side list, and reaching a side-list item applies it at once like a click: a source on its own (tags cleared), a tag as the only tag (source kept); clicking a tag still toggles several, and "All songs" (clicked or reached) clears both. When the filters leave the library empty it reads "No songs match these filters · Shift+↑ to All songs" (the key in effect). A side-list filter that hides the main selection selects the first item shown (the bookmark manager asks first about an unsaved duplicate). **Next / Previous tab** [`]` / `[`, character keys] switch Library ↔ Bookmarks and the settings window's tabs, wrapping around; in the song picker they move focus between the two lists, alongside ←/→ (which stay picker-only).
91. **List keys work at the page level:** while the song picker, library or bookmark manager is open, the list and tab keys work wherever focus is — except while a key is being recorded, while typing (a page's own search field still passes on keys that type nothing: ↑/↓, Shift+↑/↓, Enter; ←/→ and characters stay with the text), on a focused control that uses the key (sliders, the timeline, range sliders, segmented controls, tab lists, combo boxes; buttons keep their Enter), or while another dialog is open on top. Every list always shows its selection (the current item, or the first one on open), the same with or without focus; moving it scrolls it into view, and focus follows when it was on a row of that list.
92. **Loop nudges:** Loop start −1 / +1 bar and Loop end −1 / +1 bar (Player, no default keys), and the −/+ buttons beside the loop popover's From and To fields. Each nudge goes through `adjustLoopRange` (the range stays inside the song; one end pushes the other), shows the new range at once in the HUD label and the fields, and applies — turning the loop on, with one jump to its start (decision 8) — once nudging pauses for 400 ms (the range slider's key settle, decision 81). With the loop off, nudges start from the last range. With a bookmark loaded they are temporary changes (decision 69).

93. **Welcome** (`#/welcome`, docs/design/m7-7/source/QGWelcomeA) is shown over the player's scene, loaded with the resume entry, paused, blurred (9 px, saturate 120%) and dimmed; of the HUD only the app menu shows, Home lit, and the player's keys rest. It holds: the local date and a greeting by hour — "Good morning" 5–12, "Good afternoon" 12–18, "Good evening" 18–23, "Good night" 23–5 — with the profile's name in the secondary colour ("Welcome back" for a profile still named "Me"); the profile chip (top right); "Pick up where you left off" (decision 94); **This week** — minutes in the calendar week so far (the locale's first day), "+25% vs last week" against the same days of last week (hidden when those had none), a 7-day chart with today in the primary colour and empty days as a faint stub; **Last 12 weeks** — the practice calendar (decision 98) and the current streak ("4 days in a row", counting while today or yesterday was practised; hidden at 0); a rotating highlight (decision 95); and **Maybe next** (decision 96). The cards link "See all stats".
94. **Resume:** the profile's last opened entry (`lastOpened`) also stores the bar where playback last stopped, updated when playback pauses, stops or ends and when the player is left. Welcome's card shows the song, composer, the bookmark line (icon and name, with its summary for a named bookmark; "Full song"), its range bar with a marker at the stored bar, and "Last played yesterday at 21:40 · stopped at bar 26 · 9 plays · 14 min" (or "Not played yet"). **Resume** has the focus on arrival and answers Enter ("Open the selection", decision 90): it returns to the player, paused at that bar — inside the loop, or at the loop start by the loop-bounds rule (decision 8). **Choose another…** opens the song picker; loading from it opens the player. With no play records yet the card offers the loaded song: "Start with Minuet in G".
95. **Highlights** rotate one at a time, cross-fading every 8 s, paused while hovered or focused, with dots that show and select the position (a fade only, so reduced motion keeps it). Candidates, only those with data, at most five, in this order: a bookmark's range played at least 5 points faster in the last 30 days ("B section went from 70% to 85% this month", with a small trend line and "Minuet in G · 31 plays since 3 Nov"), a milestone passed in the last 30 days (10 / 25 / 50 / 100 hours, 100 / 500 / 1000 plays), the favourite song this calendar month (by time), the most practised bookmark this calendar week, and the longest session this month.
96. **Maybe next:** up to two chips — the most practised bookmark not played for 7 days or more ("Arpeggio run · Canon in D · 12 days ago"), and the first song (library order) never played, other than the one the resume card offers. A click loads it and opens the player.
97. **Stats page** (`#/stats`, docs/design/m7-7/source/QGStats), per active profile, over the last-frame snapshot like the library: "‹ Player" and Home, "Stats · ⟨profile⟩", the range **7 days · 30 days · 12 months · All** (rolling windows ending today; 12 months from the same date a year ago), a song filter (All songs, or a song with practice) and **Export CSV** (decision 100). Six headline numbers: practice time, sessions, average session, days practised ("17 of 30"), plays, longest streak (with "current 4"); practice time, sessions and plays show the change against the previous window of the same length ("+18% vs previous 30 days", "+3"), none for All or when that window was empty.
98. **Stats charts**, all from the play log in local calendar days: **minutes per day** for 7 and 30 days, per week for 12 months, per month for All (the current one in the primary colour; a recessive grid at round minutes); **top songs** by time — with a song selected, its **top bookmarks** plus Full song and "Other setups" (neutral); the **practice calendar**, 26 weeks (52 for 12 months and All), cells shrinking to fit, shaded in fixed steps: none / 1–14 / 15–29 / 30–44 / 45+ minutes, today in the primary colour, with a Less–More legend; **when you practise**, weekday (from the locale's first day) × morning 5–11, midday 11–14, afternoon 14–18, evening 18–23, night 23–5, a stretch split at band and day boundaries, shaded by quarters of the busiest cell; **tempo progress** for a chosen bookmark (with practice), per calendar week the highest tempo % on that song with exactly its bar range (any setup), from the window's start but at least 12 weeks back, as a 2 px line with 8 px points and the latest value labelled; fewer than two weeks shows a short empty state.
99. **Charts are accessible:** one data hue (the secondary colour) with the primary colour only for today / the current period — keyed by a swatch, never by a colour name; values are always printed or in a tooltip (hover; bars and tempo points also on keyboard focus, value first); every card has **Show as table**; no chart relies on colour alone. Charts are hand-drawn SVG (no chart library).
100. **Export CSV:** the play records of the current range and song filter, oldest first, one row per record: date and time (local), song, bookmark name or "Full song" / "Other setup" / "Deleted bookmark", minutes, plays, tempo %, loop, hands, pre-roll, metronome; UTF-8 with a byte-order mark and a header row, CRLF line ends; the file is named `pianomeister-⟨profile⟩-⟨7-days|30-days|12-months|all⟩.csv`.

101. **Overview drawing** (docs/design/m8/source/QGOverviewA strip, QGOverviewB editor): a piano roll of the loaded song's hand-assigned notes in their pitch-class colours (this palette), right hand at full strength, left hand at 50%, hidden channels not drawn. The x-axis is musical time (ticks), so bars of different meters get their true widths; bar lines with every 4th bar (1, 5, 9…) stronger and numbered (every bar numbered when there is room), beat lines faintly in the editor. Pitch runs low to high, bottom to top, fitted to the notes' range with a small margin. A 2D canvas, device-pixel-ratio aware, redrawn only on zoom, scroll, resize, theme or hand-assignment changes; the playhead, loop band, selection and lanes are a separate light layer. Nothing is drawn while the strip is closed.
102. **Overview loop band** in the secondary colour with drag handles at both ends (the bar number shows while dragging, always in the editor). A drag follows the loop rules: the range stays valid (`adjustLoopRange`), applies on release with one jump to the loop start (decision 8), and is temporary or global like any loop change (decision 69).
103. **Overview selection:** dragging across the notes selects whole bars (primary colour, dashed outline). Releasing shows the **action bar** beside it: "Bars 41–48 · 8 bars", **Loop these bars** (primary; a committed loop change), **Save as bookmark** and ×; Esc clears it, and nothing changes until an action is chosen. Save as bookmark saves the selection's bars with the current tempo, hand modes, pre-roll and metronome mode, auto-named, with no exact duplicates (decision 78), **without loading it**: playback isn't disturbed. Its toast reads "Saved "⟨name⟩"" with **Load**, **Rename** and **Undo**; an existing match reads "Already saved as "⟨name⟩" · no new bookmark created" with **Show**. A click without a drag seeks to the start of the clicked bar (the loop-bounds rule applies: with a loop on, a bar outside it lands on the loop start).
104. **Overview playhead, zoom and keys:** the playhead is live (white, as on the timeline). Zoomed in, the view follows it while playing; scrolling by hand turns **Follow** off until the next Play or a click on the **Follow** chip, which shows only while following is off. Ctrl/⌘ + wheel and pinch zoom around the pointer (4 bars to the whole song); the wheel and two-finger scroll pan. The roll is focusable: ←/→ move a bar cursor, Shift+←/→ extend a selection, Enter = Loop these bars, `B` saves the selection (Save as bookmark, decision 103), Esc clears; while it has focus it keeps its arrow keys. Screen readers hear the bar range ("Selected bars 41–48 · 8 bars").
105. **Overview strip** (in the player): opened by the timeline's chevron or **Toggle overview** [`V`]; the open state is kept across reloads. Its header: "Overview", the song and its bar count, the right/left hand legend, a zoom slider (Whole song … 4 bars), Follow (when off), **Open editor** and the close chevron. A **bookmark lane** above the notes shows the song's bookmarks as labelled ranges (up to 2 rows, then "+N"), the one playing highlighted (decision 69); a click **loads** it. The lane is one Tab stop: ←/→ move between bookmarks in a row, ↑/↓ between rows, Enter loads (in the editor's lanes Enter selects). The strip never edits bookmarks. It is hidden on Welcome and in the loop editor.
106. **Loop editor page** (`#/editor`): the player stays mounted behind it with the scene frozen, blurred and dimmed and its HUD hidden. Opened from the strip's **Open editor**, the bookmark manager's **Open in editor** (which loads that bookmark's song first if it isn't the loaded one, as Full song) and **Open loop editor** [`E`; `E` again, or "‹ Player", returns]. The loop editor is a full page like the Library and Stats: no app menu; its header has "‹ Player" and **Home**, "⟨Song⟩ · Overview", zoom presets **Whole song · 32 · 16 · 8 bars**, right/left hand visibility (view only, remembered on the device) and **Play from bar N**, which reads where play will really start: the selection's first bar, else the loop start, else the bar cursor, and with a loop on a bar outside it becomes the loop start (decision 8). Below the notes (with C labels on the left) the **bookmark lanes** show all of the song's bookmarks stacked when they overlap, and a **minimap** shows the whole song, the loop and the view as a draggable window. The side panel shows the selected bookmark — name, summary, From/To bar fields, Played/Practice/Last, **Load in player**, **Edit in bookmark manager** — or, with none selected, the selection's or the loop's bars with **Loop these bars** and **Save as bookmark**.
107. **The loop editor edits bookmarks:** dragging the selected bookmark's ends or body, or its From/To fields, changes its range — saved on release, the automatic name following (decision 76), "Same settings as "⟨name⟩"" when it then matches another (decision 78), kept inside the song — with a toast "Bars of "⟨name⟩" changed to 17–36" and **Undo**. Playback keeps running: Space and the transport keys work (not `P` or `V`). Editing the **loaded** bookmark's range moves the loop with one jump to its start, unless a temporary loop change is active (it wins, decision 69).
108. **Milestone 9 process:** decisions 109–121 are built with provisional defaults close to the earlier look (glow subtle), then tuned live in a session; the tuned defaults and 3–5 built-in looks then replace the provisional values here.
109. **Selective bloom:** only emissive elements glow (lines, note edge rims, sounding and pulsing note fills, emissive fill styles, cage borders, lit key overlays, the light cone, additive particles). Each is drawn a second time in a small glow scene of its own (a "glow twin": same geometry, glow-only shader, shared uniforms and buffers; synced with its mesh only when settings or the song change, so the main scene isn't walked twice per frame) into a half-float target sized by the quality preset (8-bit where half float isn't renderable); keys and 3D heads draw black there and write depth, so they hide glow behind them. three's `UnrealBloomPass` blurs it and a mix pass adds only the blur to the frame (with the optional vignette) — never the glow scene itself, so an element keeps its own brightness and gains a halo, and the Classic look stays the Classic look with bloom running. Bloom strength, radius and threshold are appearance settings (part of a look). Glow fades through the same haze as everything else.
110. **Quality presets** (Render quality): **Off / Low / Medium / High** set the _cost_ settings only — bloom resolution (none / ¼ / ½ / full), particle budget (512 / 1 024 / 2 048 / 4 096) and shader detail; changing one afterwards shows "⟨Preset⟩ · modified". **Off is exactly the pre-milestone-9 pipeline.** Shader detail also gates key light: Minimal has no spill, cones need Medium or High (their switches are greyed out otherwise). A greyed-out setting says what it needs ("Needs shader detail Medium or High", "Needs bloom (quality Low or higher)"): under the row, or — when three or more visible rows in a section are greyed out for the same reason — once at the top of the section, with the rows greyed out silently. When one reason implies another, only the root cause shows (names off → "Needs note names on", not also "…on notes"). Default **Medium**, **Low on tablets** (`(pointer: coarse)` and a short screen side ≤ 1024 px). The stored settings record which device default applied, so reset and "modified" are per device.
111. **Lines:** the now line (thin / glowing / neon), highway borders, octave lines on every B/C boundary (option: also E/F) and the bar and beat lines (optional faint glow) — each with on/off, colour, width and glow. Colours: White, Primary, Secondary, Custom, and for the now line Pitch (the colour of the key underneath; black keys win over their width).
112. **Note fill styles**, chosen separately for heads and sustains; each must be recognisable at a glance:
    - **Solid:** flat note colour. **Gradient:** bright at the head, fading toward the tail.
    - **Hot core:** bright in the _middle_ — a filled body with a white-hot centre band, a warmer tint of the note colour, deep saturated colour at the edges; hottest at the head, cooling slightly toward the tail. When see-through, the white band fades less than the body.
    - **Glass:** a tinted glass block — a note-coloured body you can see into (fairly solid at 0 % transparency), a soft wide diagonal sheen, a thin smooth brighter rim; with 3D heads the top face is lighter than the sides.
    - **Outline:** dark interior, bright border (milestone 9's first "Neon"; stored values migrate).
    - **Neon:** a neon-sign tube inset just inside the edge — near-white core line, saturated note colour falling off both sides, a dim note-coloured haze inside — on the glow scene; optional flicker (off by default; still while paused and under reduced motion).
    - **Diagonal stripes:** settings per use (head fill, sustain fill, each cage): stripe A and B colours (notes: note colour / darker note colour / custom; cages: custom), A and B opacity, width (world units, shown in mm), balance (share that is A, 20–80 %), angle (−75° to 75°, default 45°) and drift (default off). Edges are box-filtered with screen-space derivatives, and stripes narrower than ~2 px blend into the A/B average, so there is no moiré or shimmer at any distance.
    - **Smoke:** soft wisps stretched along the note, drifting toward the tail.
    - Outline and Neon draw their own edge, so the edge glow settings are greyed out (with that hint) while both fills are one of them.
    - Patterns are computed in each note's own lane and world-length coordinates, never screen-aligned. Every fill respects both sustain transparency settings, linearly; glow and every additive part of a fill scale with the note's opacity.
113. **Note light:** an edge rim on heads and sustains (constant world width, following perspective and taper); a note-on pulse on the key overlay and the whole note (amount, decay in ms, velocity-scaled; after a seek or loop wrap only notes starting after the jump pulse, like decision 9; seeking while paused never starts a pulse); sounding notes glow brighter, with optional breathing.
114. **Note names:** off / on notes / under the keys / both; the octave on every C or on all notes; sharps or flats. Drawn in the UI font (Inter Tight semibold) from an atlas holding text and a soft halo — never a box. **On notes:** label style _Facing camera_ (default: upright, a constant size on screen, never stretched) or _Flat on note_ (lying on the note, as wide on screen as a facing label); text size 10–18 px (default 12); text colour Auto (the note colour tinted ~75 % toward white) / Note colour (lifted ~30 % toward white, so it separates from its own note) / White / Dark, with a soft halo (dark, or light behind dark text, at least 85 % there so it never reads dark-on-dark; "Text shadow" 0–100 %, default 60 %); "Label repeated notes" _First of a run_ (default) / _All_: a run is consecutive notes of one pitch with no gap over a beat (a quarter, `ppq` ticks), decided from the music once per song, and only its first note is labelled (stack slots then count only labelled notes); shown within a share of the look-ahead (default 40 %) and faded over a further share (default 15 %) — a ramp, never a hard cut, and fully transparent where a label would be under ~8 px; it fades out over the last 5 % before the now line, where (with Both) the key-top label takes over; anchored ahead of the head (default), on it or behind it on the sustain (short notes fall back to on the head), offset along the note (±1 lane width) and raised above it (0–24 px, facing labels); "Avoid overlaps" (default on) — labels never jump around or blink: (1) **stack slots** are decided from the music once per song: notes starting at the same tick in neighbouring lanes (centres under ~1 white-key width apart) take fixed slots in pitch order, each the lowest slot no neighbour holds, a slot lifting the label by one label height + 2 px (flat labels: one label depth along the note), so a label never moves while on screen; (2) the overlap pass is **one-way**: nearest first, a label entering range shows unless it overlaps a shown one (2 px clearance); a hidden label fades in (0.15 s) only once it clears every shown label by 4 px; a shown label stays shown until its handover fade at the now line; (3) a seek, or a change to how labels are laid out, places every label afresh at once, with no fades. Optional subtle glow (on the glow scene, tinted with the note colour). Reduced motion keeps the distance fades; reveals then apply at once. **On keys:** the same font near the front of the key top, moving with the press; "Key label size" 8–16 px on screen (default 11, separate from the note text size), upright on screen and shrunk to fit the key, and a label that would be under ~7 px fades out rather than render a smudge; neutral while the key rests (dark on white keys, light on black), tinted toward the note colour while it's held. The note-label rows stay visible, greyed out with a hint, while names are off or only on keys. No colour by hand (milestone 10).
115. **Cage renderer:** regions on the highway (tick range × key range, or full width) with a border (width, colour, glow, corner radius) and a fill (the note fill styles, colour, opacity), drawn under the notes — and never through them: the notes mark the stencil buffer first, so a translucent note shows the highway, not a cage fill — perspective-correct, clipped at the now line (no border at the clip). Regions can be replaced at runtime and may leave their start or end open, so milestone 10's per-hand, per-bar cages join without lines between bars.
116. **Pedal cage:** sustain pedal periods (assigned channels, merged) form a full-width cage; its default style is decision 13's band.
117. **Now-line effects:** on note-on (one or several): sparks, scaling sparks, flame burst, explosion (flash ring + debris), glitter puff; while a note sustains: none, glow, embers, small flames, smoke wisps. Each with size, count, lifetime, spread and velocity scaling, coloured by pitch. Particles move on the GPU from their spawn data, in one ring-buffer pool the size of the quality preset's budget, so under load the oldest go first; smoke blends differently and has its own pool of a quarter of the budget. Reduced motion: one still flash per onset and no sustain particles.
118. **Key light:** lit keys spill a soft coloured light onto neighbouring keys and can cast a light cone down the key toward the player (strength, spread).
119. **Animation clock:** flicker, breathing, smoke, stripe drift and particles run on wall-clock time (not the song position), stop while the scene is frozen, and stop under reduced motion (decision 54). **Paused frames settle:** when playback pauses, pulses, flashes and particles already in flight finish over their normal duration on the wall clock; looping animation and sustain particles stop; then the frame holds still. On resume, notes up to the paused position don't pulse again. A pinned animation clock (`?animTime=`, visual tests) shows paused pulses already settled.
120. **Settings schema v6:** the milestone 9 settings; v5 is migrated: the pedal band's colour and opacity become the pedal cage's fill; everything else keeps its key (lane, bar and beat lines keep their colours, "Now-line effects" stays the effects' master switch) and new settings get their defaults. Shortcut overrides stored by v5 carry over. The stored shape becomes `{ version, settings, shortcuts, looks, deviceClass }`. **v7** (milestone 9 round 3): the first Neon fill becomes Outline (settings and saved looks); the shared stripe width and drift move into the head, sustain and pedal stripe groups (the pedal takes the width only if it was changed from the old default, so its new wider default applies otherwise); the note-name settings of decision 114 are new.
121. **Looks:** a look holds every appearance setting (highway colours, lines and glow, note style, effects, pedal and cages, note names, bloom strength, radius and threshold) — not the camera, keyboard dimensions, look-ahead or render cost. A **Look** picker at the top of the playfield sidebar switches between built-in looks ("Classic" = the pre-milestone-9 look) and saved ones; picking one applies all its values with an Undo toast; a change afterwards shows "⟨Look⟩ · modified" with Save / Save as new; "Save current look…" names a new one. Device-wide like settings, not in the library backup. **Copy look** puts the current look on the clipboard as a `.pmlook.json` file (milestone 9.1's format; an unchanged look keeps its id and name, a changed one gets a new id and "(modified)").

## Key and note visual behavior

**Piano keys**

- At rest, keys are plain white or black.
- As a note approaches, its pitch color is laid over the key and fades in, from fully transparent to more visible. The fade runs over a short window before the note starts (default: 1 beat, tempo-relative, configurable).
- While the note sounds, the key shows the pitch color at full strength.
- When the note ends, the key returns to white or black, unless the next note on that key is already fading in.
- Repeated notes on one key: a sounding note always takes priority over the next note's fade-in.

**Effects on the "now" line** (the zero-lookahead line at the near end of the highway, directly above the keys)

- **Note start:** a short, bright burst in the pitch color, such as a flash or a small spray of sparks.
- **While held:** a mild, steady effect in the pitch color, such as a pulsing glow or a small flame. It should be clearly visible but not distracting.
- **Note end:** the held effect fades out quickly.
- **Choices (milestone 9):** the note-start and while-held effects are selectable (decision 117), with key light (decision 118) and the note-on pulse (decision 113).
- **Performance:** instanced particles from a fixed ring-buffer pool sized by the quality preset (decision 110); bloom is optional and selective (decision 109), never a threshold on the whole frame, so dense chords stay smooth on tablets.
