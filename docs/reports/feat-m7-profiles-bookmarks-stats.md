### Decisions I made that weren't in the instructions

1. **"Me" keeps the id `default`.** Existing hand assignments already belong to it, so the v3 upgrade only creates the profile and moves the last song. Two devices' "Me" therefore collide on import, which is exactly what the collision dialog is for.
2. **Explicit loads start fresh.** Picking the already-loaded bookmark again (picker, manager "Load in player", library Play) drops its temporary changes. Returning to the player from the library or manager keeps them. Otherwise "reload the bookmark → saved values" couldn't work.
3. **The Practice tab stays global.** With a bookmark loaded, its pre-roll rows still edit the device-wide default (what Full song uses). Only the loop popover's pre-roll and the Audio tab's hand modes are temporary, as you listed.
4. **Hands in the manager:** one row per hand (label, On · Mute · Solo, reset) instead of the source's single "Both / Right only / Left only" control, which can't express solo or both muted.
5. **Summary wording:**
   - When only one hand is soloed, the summary says "right only" or "left only" rather than "right solo". Both muted reads "both muted".
   - **Full song's hands follow the Audio settings**, so its summary may show e.g. "left muted".
6. **Import dialog facts for empty sides:**
   - no practice time reads "no practice time";
   - never practised reads "not practiced yet";
   - Replace with no history says "practice history (none)".
   - For "N days" the date reads "last practiced 4 days ago".
7. **Collision step order** follows the backup's profile order (by id), so a backup with Anna and Me asks about Anna first.
8. **Play-log details:**
   - "At the range start" means at or before the effective range's first bar, i.e. playing from the parked stop position or in its pre-roll.
   - A transport `resync` (a skipped loop pass in a background tab) voids the pass.
   - A pass is written at once on each wrap as well as every 30 s, so the picker updates live.
9. **Charts:** zero days are a faint stub, today is in the primary colour and other days in the secondary (decision 52). The sources use the primary colour for both.
10. **The picker is prefetched when idle.** The picker chunk loads once the player is idle, so `O` doesn't wait for it, and the library list loads in the background after the first song opens. The `CI=1` runs showed the picker opening with an empty list, so the first ↑ did nothing.

### Known issues and open questions

1. **Picker cells at 1024 px:** long bookmark names truncate in the picker's Load list (e.g. "B secti…").
2. **Background tabs:** a session's end is the last playback written. A stretch still running when the tab closes loses at most 30 s (by design). A `pagehide` write may not finish.
3. **Profiles flow on the preview:** 23.5 s against the 30 s limit. If it creeps up, it can be split in two.
4. **Dev-server flakes (open):** two tests failed once each across four full dev runs, never on the preview build.
   - My guess is a slow on-demand Vite transform of the newly larger lazy chunks while 4 workers run, but I haven't confirmed it.
   - The picker chunk is now prefetched when idle, which helped on the preview but doesn't cover a click right after load.
5. **Practice tab and the session layer:** should the Practice tab also show a "Temporary for…" note while a bookmark is loaded? Today it edits only the global default (decision 3 above).

### Decisions I made that weren't in the instructions

1. **"no pre-roll"** is the automatic name's pre-roll part at 0 beats ("always all parts"). The pre-roll **mode** isn't in the name (your example doesn't have it), so two bookmarks can share a name while differing only in muted/quiet.
2. **Revert to bookmark always jumps** to the bookmark's loop start, even when only the tempo was changed: it puts the bookmark back as it loads. Per-field resets jump only for the loop.
3. **Saving doesn't jump.** "Save as bookmark" and the "Already saved" case load a bookmark whose loop is what's playing, so the playhead stays (not counted as "loading a bookmark").
4. **Keyboard steps on the range slider commit each step** (each arrow press applies the loop and jumps); only pointer drags wait for release.
5. **Composer order:** "Composer: X" / "by X" in a text event → a known composer in the texts, sequence name or file name → the copyright holder. You listed copyright with the meta events (before name matching); I put it last because on files like piano-midi.de's it names the sequencer ("© Bernd Krüger"), which would beat "Debussy" in the file name. "Sequenced/arranged/transcribed… by X" is ignored. Easy to swap back if you prefer your order.
6. **The composer's name is dropped from the start or end of a guessed title** ("Clair_de_Lune__Debussy" → "Clair de Lune", "Bach_Invention…" → "Invention No. 8 BWV 779"); a catalogue prefix that implied the composer stays ("BWV 772"). "No.8"/"No10" → "No. 8"/"No. 10" and "op9" → "Op. 9" besides the BWV tidy.
7. **Library composers win by surname** (keeping their spelling: "J.S. Bach" over the built-in "J. S. Bach"); a parenthesised attribution doesn't count ("Christian Petzold (attrib. J.S. Bach)" matches Petzold).
8. **Guess from file is for uploads only** (bundled songs have curated details and no stored bytes to read here); it saves the guess as an edit right away, like typing it.
9. **Undo after saving** restores the exact previous state (bookmark or Full song, with its temporary changes), not just "Full song".
10. **Edits in the manager save on each change** (no 300 ms debounce), because the draft logic needs every edit to be decided at once. A reload that overlapped an edit could then overwrite it in memory (the preview run caught it), so the store re-reads when an edit happened during a read (unit test reproduces the race).
11. **The "Save as bookmark" button text lost its ellipsis**, since it no longer opens anything.
12. **The draft row** sits right after its source and reads "Unsaved duplicate" in italics; deleting a draft just drops it (no Undo toast); Duplicate is disabled on a draft.
13. **Toast actions:** the toast store gained `showActions` and actions on Undo toasts; Esc closes toasts as before (Reka), so closing the loop popover with Esc also closes the save toast.

14. **Metronome mode names:** the stored values stay the settings' `off` / `preRoll` / `always` (you wrote "preroll"); labels are "Off · Pre-roll · Always" in the manager and "Off / Pre-roll only / Always" in the Audio tab as before.
15. **Metronome toggle value text:** "pre-roll" shows beside the icon in pre-roll mode (like "85%" beside tempo), so the two on-modes can be told apart; "always" shows just the lit icon. The last non-off mode is remembered for the session (not stored).
16. **"Switch" for Hide controls** is the app's existing boolean toggle (a styled checkbox, like the other on/off settings), not a new switch component.
17. **The tempo step also drives the bookmark manager's tempo slider**, so the two tempo sliders behave alike. The slider's ends move with the step (e.g. 28–200 % for 4 %) to keep 100 % on the grid; a saved tempo off the grid (85 % with a 4 % step) still shows and loads exactly.
18. **Widget keys aren't commands:** the timeline and sliders (arrows, Home/End), text fields (Enter), tag and combo boxes keep their keys; putting them in the registry would make the timeline's ← → conflict with the player's ← → in the same scope. Tempo has no shortcut today, so "tempo keys" are the slider's arrow keys.
19. **Two "Temporary for …" notes in the Audio tab** (under the hands and under the metronome) so each sits by the controls it explains.
20. **Setup split, details:** a change while paused is only remembered; the new record starts in the same session; changes made by a load are part of that load (no extra record). The `temporary` flag is "any temporary change", not which one.

21. **Upload toast for one song** names it ("Added "Pedal demo"") rather than "1 song added"; several duplicates read "2 songs already in your library". The notice under the list (with rejection reasons) stays.
22. **Clearing filters:** only the ones that hide the selected song are cleared; a tag filter that hides it is cleared entirely (not tag by tag). The toast says "filters cleared to show it" even when several new songs were hidden, since the selected one is the "it".
23. **The pass-count e2e test has 60 s** instead of 30 s: under the full preview suite it once ran out while loading samples (4/4 passed when repeated alone).
