# Milestone 4 — Song library, uploads, song details, backup

Read CLAUDE.md and docs/brief.md first, then plan the following. Work on a branch (`feat/m4-library`), not `main`.

## Goal

A real song library: bundled songs from a manifest plus user uploads stored in IndexedDB (Dexie), a Library page with search / sort / group / tag filters, a details panel per song (metadata, tags, hand channels, meter override), bulk export/import of the library, and protection against Safari's storage eviction. The player stays the home page and reopens the last selected song.

## Step 0 — Update the brief

- **Milestone 4** line: "Library page, bundled manifest, uploads (IndexedDB), song details panel (metadata, tags, hand channels, meter override), library export/import, web app manifest."
- Data model: add **SongMeta** (songId, display title, composer, tags — user edits, shared across profiles) and **StoredUpload** (songId, file name, bytes, addedAt).
- Add under "Confirmed decisions", continuing the numbering (from **26**):
  - **Library page** at `#/library`: searchable, sortable list; group by composer or tag; filter by tag and source. Picking a song opens it in the player; the player has a Library button.
  - **Startup:** the player (home page) reopens the last selected song (from milestone 5: the last song *or bookmark*). First run falls back to the first bundled song.
  - **Song metadata is editable for every song** (bundled and uploaded): display title, composer, free-form tags. Edits are stored locally and shared across profiles; the original values are kept and can be restored ("Reset to original").
  - **Uploads:** multiple files at once; `.mid`/`.midi` only; max 2 MB each; duplicates detected by content hash (against bundled songs and other uploads) are skipped with a message; uploads can be deleted (with confirmation). Bundled songs can't be deleted.
  - **Hand channel fallback:** if neither channel 0 nor 1 has notes, assign by average pitch — highest-average channel → right hand, next → left, others hidden; a single channel → right hand. Users can change it in the song's details panel.
  - **Song details panel** (inside the Library page): metadata and tags, file facts, hand channel assignment, meter override editor, delete (uploads only), Play.
  - **Library export/import:** one `.zip` containing all uploaded MIDI files plus a versioned `library.json` (metadata edits and tags for all songs, meter overrides). Importing skips duplicates; for songs already present, local metadata edits are kept and the import report says so.
  - **Storage protection:** request persistent storage (`navigator.storage.persist()`) on the first upload and show the storage status in the Library; ship a web app manifest so the site can be added to an iPad/iPhone home screen (home-screen apps aren't subject to Safari's 7-day storage deletion). Offline support (service worker) stays in milestone 6.
  - **Adding bundled songs:** drop the `.mid` into `public/songs/`, run `npm run songs:manifest`, then fill in title/composer/tags in the manifest.

## Dependencies

- `dexie` (storage, as in the brief), `fflate` (zip for export/import), and `fake-indexeddb` as a **dev** dependency for Node tests. No others without asking.

## Bundled songs

- Move the three real songs into `public/songs/` (keep `pedal-demo.mid` in `test-fixtures/` — it is not a library song). Update tests to read them from the new location; no duplicate copies.
- `scripts/build-song-manifest.mjs` (`npm run songs:manifest`): scans `public/songs/`, computes each file's SHA-256 id and basic facts (duration, bars, time signature, BPM), and writes/updates `public/songs/manifest.json` — preserving hand-edited `title`, `composer`, `tags` for existing entries; new files get the file name as title.
- A unit test fails if the manifest is out of date with the files (missing entry, stale hash).
- Initial metadata: Minuet in G — Christian Petzold (attrib. J.S. Bach); Canon in D — Johann Pachelbel; Invention No. 1 in C major, BWV 772 — J.S. Bach. Tags: `baroque`.

## Data layer (`src/data/`)

- Dexie database, schema version 1, tables (names are suggestions): `uploads` (songId, fileName, bytes, addedAt), `songMeta` (songId → title?, composer?, tags[]), `meterOverrides` (songId), `handAssignments` (`[profileId+songId]`, using a built-in profile id `"default"` until milestone 5), `appState` (lastSongId).
- A `Library` service that merges the bundled manifest + uploads + metadata into one list of library entries, loads a song's bytes (fetch for bundled, Blob for uploads) and builds the Song with its hand assignment and meter override applied.
- Upload pipeline: validate extension and size → hash → duplicate check → parse with `importMidi` (reject unparsable files with a clear reason) → store. Returns a per-file result (added / duplicate / rejected + reason).
- Persistent storage request on first upload; expose `navigator.storage.persisted()` and usage/quota estimate for the status line.

## Pure logic (unit-tested in Node)

- Hand channel fallback (the rule above) given channel stats.
- Library list operations: search (title, composer, tags; case/diacritics-insensitive), sort (title, composer, duration, date added, source), group (composer / tag / none), tag filter, source filter.
- Tag normalization (trim, collapse spaces, case-insensitive dedupe, keep the user's casing of the first occurrence).
- Metadata merge: edit over original; reset.
- Export/import: build and read the zip + `library.json` (versioned; reject unknown major versions); import merge rules above. Round-trip test.

## Library page (`#/library`)

- Header: search box, sort, group-by, tag filter chips, source filter (all / bundled / uploaded), Upload button + drag-and-drop anywhere on the page (with a visible drop overlay), Export and Import buttons, storage status line (persisted yes/no, usage).
- List rows: title, composer, tags, duration, bars, time signature, BPM, source, date added (uploads).
- Selecting a row opens the **details panel** (side panel on wide screens, full-screen sheet on narrow):
  - Metadata: display title, composer, tags (with autocomplete from existing tags); "Reset to original".
  - File facts: file name, format, ppq, tracks, channels with note counts and pitch range, tempo and time-signature events, duration, bars.
  - Hands: each channel → Right / Left / Hidden, plus "Swap hands" and "Restore default".
  - Meter override: numerator/denominator, bar-1 start (pick as bar:beat or tick), helper "Start bar 1 at the first note", resulting bar count preview, Clear.
  - Delete (uploads only, with confirmation). **Play** opens the song in the player.
- Upload results shown as a short summary (e.g. "2 added, 1 duplicate, 1 rejected — not a MIDI file").
