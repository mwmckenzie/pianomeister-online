# Milestone 10.5 — Hand detection and split

Added 2026-11-24. Branch: `feat/m10-5-hands`, from `main` (milestone 10 merged).

## Goal

Work out which notes each hand plays, even when both hands share one channel. Show the result with a confidence and the reasons, let the player correct it, and use it everywhere the app needs a hand: note colours, mute and solo, and the hand cages. The assignment is stored with the song. The MIDI file is changed only when the player exports a split copy.

## Definitions

- **Voice:** a (track, channel) pair, id `"track:channel"`, as in the brief. It replaces the channel as the unit in the Library's hand picker.
- **Role (per voice):** Right, Left, Split or Hidden. Hidden is the app's existing Hidden (the brief's "Ignore" and "Leave as is"): its notes are not shown and belong to no hand.
- **Assignment:** the resolved hand of every note: right, left or none (Hidden). Note ids are the brief's `track:noteOnEventIndex`. They're stable because the stored MIDI file never changes.
- **Song confidence:** the lowest confidence among the voices set to Right, Left or Split by detection. It is shown as a whole percent.

## Where the hand comes from (one function)

Milestone 10 made `handOf(note)` the only source of a note's hand. In this milestone:

1. `handOf` reads the song's resolved assignment: user flip if any, otherwise the voice role, otherwise for a Split voice the algorithm result.
2. **Audit every remaining use of the old channel → hand map**: note colours, labels, mute and solo, the hands toggle, stats, cages, playlists and listening mode. Route each one through `handOf`, so nothing reads channels for hands any more. List what you found in the plan.
3. Audio mute and solo must work per note. If playback currently routes or mutes by channel, change it to check each note's hand, and say in the plan how.

## Storage

- **Dexie:** add a new version with a `handAssignments` table keyed by `songId`. Each record holds:
  - `roles` (voiceId → role);
  - `algorithm` (id) and `params` (only values that differ from the defaults);
  - `flips` (noteId → 'R' | 'L');
  - `detection`: the guesses with role, confidence and reasons, plus the summary, so the Library doesn't re-run detection to show them;
  - `confidence` (the song confidence);
  - `source`: 'detected' or 'user'. It becomes 'user' as soon as the player changes a role, a flip, the algorithm or a parameter, and saves;
  - `detectorVersion`: a number, starting at 1.
- **Cache:** store the resolved per-note hands as a compact string (one char per note: R, L or -), with a hash of its inputs: algorithm, params, roles and flips. Recompute only when the hash changes. The beam search must not run on every song load.
- **Backups:** add the table, as backup format 1.5. Importing 1.4 or older still works: those songs get the migration below.
- **Migration of existing songs:** convert each song's channel → hand map into voice roles. Every voice on a channel gets that channel's role.
  - If the song's map is still exactly the default that upload creates (find that rule in the code and name it in the plan), mark it `source: 'detected'` and queue it for the background pass.
  - Otherwise mark it `source: 'user'`. **Detection never touches it.**

## Detection

- **On upload:** run detection and the default split (Phrase look-ahead), store the result and apply it straight away.
  - Song confidence below the hint threshold (setting, default 70 %): show the hint (below).
  - Detection never asks a question or blocks the upload.
- **Background pass:** once, after the app is idle, run detection on every song queued by the migration. Rules:
  - One song at a time, yielding between songs (`requestIdleCallback`, or `setTimeout` 0 as a fallback). Pause while a song is playing.
  - Skip any song whose record became `source: 'user'` in the meantime.
  - When it's done, show one quiet toast: "Hands detected for N songs · K to check". Show nothing if N is 0.
  - Store a flag so it doesn't run again. A later `detectorVersion` bump may re-queue `source: 'detected'` songs only.
- **Bundled songs** get detection as well, using the same rules.

## The hint

- Song row in the Library: append "· Check hands · 58 %" to the second line, in amber (`#E9C07A` in the mockup; use the app's warning text token if there is one).
- Library details "Hands" badge: amber "Check · 58 %" instead of teal "Detected · 82 %".
- The hint clears when the player saves on the Review page, or changes any role in the Library. Either makes the record `source: 'user'`.

## Library details: "Hands" section (mockup QGHandsSummary)

It replaces the current "Channel N → Right/Left/Hidden" pickers.

- **Header:** "Hands", with a badge on the right:
  - "Detected · 82 %" (teal) when the result is detection's own;
  - "Check · 58 %" (amber) when below the threshold;
  - "Edited" (neutral) once `source` is 'user'.
- **One row per voice:** "Track 1 · ch 0 · Piano" (the track name if it has one, otherwise the instrument name), second line "412 notes · both hands" (or "right hand", "left hand", "drums", "few notes"). The role picker shows Right, Left, Split and Hidden. Changing it applies at once and saves.
- **Split summary box** (only when at least one voice is Split):
  - "Split with *method name*";
  - a two-part bar, right then left, sized by note count;
  - counts: "Right 236 notes · Left 176 notes";
  - a "Why" disclosure listing the detection reasons for every voice, prefixed by the voice name when there is more than one. It is closed by default; the mockup shows it open.
- **Buttons:** "Review hands…" opens the Review page. "Export split…" opens the export dialog.
- **Footnote:** "Stored with the song; the MIDI file is unchanged. Your own changes are never replaced by detection."
- **Warnings** (brief §7, adapted): if two voices are both Right or both Left, no warning: their notes merge, as today. If every voice is Hidden, show "No hand is shown".

## Review hands page (mockup QGHandsReview)

A full page, opened from the Library. Its route takes the song id. Back returns to the Library with the song still selected.

- **Header:** Back to "Library", the title "Review hands", a line with "Title · Composer". On the right: "Unsaved changes" text when dirty, then "Reset to detected" and "Save".
  - Leaving with unsaved changes asks "Discard changes?" with Discard and Keep editing. Esc means Back.
- **Left panel:**
  - **Voices:** the same rows as the Library, plus the confidence and the first reason.
  - **Split method:** a select with the four algorithms in registry order; Phrase look-ahead is first and marked "(recommended)".
  - **Advanced** (closed by default): controls built from the algorithm's `params` (number → slider with value; note → slider showing the note name), with help text as a tooltip and "Reset these".
  - **Result:** the bar, the counts per hand, "N notes flipped" and "N uncertain".
  - **Footnote:** "Saved with the song; the MIDI file is unchanged until you export with hands split."
- **Main area:**
  - **Legend:** Right and Left (the current note colours of the active look), "Flipped by you" (white outline) and "Uncertain" (stripes).
  - **"Compare with":** Nothing (the default) or one of the other three algorithms. It outlines the notes where that algorithm differs, dashed, and shows "*Name* differs on N notes (dashed)".
  - **"Clear flips".**
  - **Two piano-roll lanes sharing one time axis:**
    1. **"Current · by channel":** thin, notes coloured by channel. It is a reference only.
    2. **"Proposed · *method*":** the editable lane. Bar numbers along the top, C3/C4/C5 guide lines, notes coloured by resolved hand. **Click a note to flip it.** Flipping it back to the computed hand removes the flip, as the brief says.
  - The lanes cover **the whole song**, with horizontal scroll and zoom (Ctrl+wheel, and + / − buttons). If the loop editor's piano roll from milestone 8 can be reused for this, do so; say in the plan.
  - Keyboard: Tab reaches the notes in the proposed lane in time order, and Enter or Space flips the focused one. Each note's accessible name is like "F#4, bar 5 beat 2: left hand. Click to flip."
- **Uncertain notes** (brief §11, "share of the final beam agreeing on a note"): for Phrase look-ahead, follow every hypothesis left in the final beam. A note is uncertain when fewer than 75 % of them give it the same hand as the winner. The other algorithms mark nothing as uncertain. Uncertain notes are striped in the proposed lane; a flip removes the stripes.
- **Save** writes roles, algorithm, params and flips, and sets `source: 'user'`. **Reset to detected** restores the detected roles and the default algorithm and params, clears the flips and turns the comparison off; it is not saved until Save.

## Export with hands split

- Opened from "Export split…" in the Library details, and also as an option in the Library's Export menu for the selected song.
- **Dialog:**
  - Layout: "Same tracks" (the brief's in place) or "Two tracks (Right Hand, Left Hand)";
  - Right channel (default 0) and Left channel (default 1), each 0–15;
  - a warning line (brief §7) if a Hidden voice already sits on one of those channels ("Track 3 · ch 1 would mix with the left hand"), or if both channels are the same;
  - Export.
- It downloads "*Title* (hands).mid". Hidden voices are written unchanged. The stored song is not modified.
- Channel-wide events are copied exactly as in §8 (program, sustain and other CCs, pitch bend, aftertouch).

## Mockup corrections

- The algorithms are **Phrase look-ahead, Chord-aware, Moving split point and Fixed split point** (the brief's). "Hand-position cost" in the mockup doesn't exist.
- The role is **Hidden**, not "Ignore".
- The Advanced controls come from each algorithm's `params`. Phrase look-ahead's are reach, center, prior, inertia, chordMs, holdSecs and beam, not the mockup's three.
- The mockup crops to bars 1–8. The real page shows the whole song.
- The mockup's hand colours are placeholders. Use the active look's hand colours.

## Acceptance criteria

1. A one-channel two-hand upload is split automatically, with a confidence and reasons, and its cages follow the split.
2. Songs with hand settings the player changed before this milestone keep them exactly. The background pass never changes them.
3. Every place that shows, plays, mutes or cages by hand uses `handOf`.
4. Flips and roles survive reload, backup and restore.
5. Export split produces a file that round-trips through parse, with the note count unchanged, as brief criteria 9 and 10.
6. Song load stays as fast as before for a song whose assignment is cached.
7. `npm run check` passes; `test:e2e:affected` passes, including `@hands`, `@cages` and `@smoke`.
