# Milestone 9.1 — Looks v2, built-in looks, range trimming

Added 2026-11-21. This builds on milestone 9 (`m9.md`, `m9-plan.md`). Where this file disagrees with them, this file wins. Branch: `feat/m9-1-looks`, from `main` after milestone 9 is merged.

## A. Looks cover the whole playfield sidebar

A look now captures **every setting in the playfield sidebar**, in all its sections: Camera, Keyboard, Highway, Lines & glow, Notes, Note style, Effects, Pedal & cages, Note names, and Render quality's appearance settings (bloom strength, radius, threshold).

The exceptions are **device-cost settings**: quality preset, bloom resolution, particle budget and shader detail. A look never stores or changes them. They stay per device, so a look made on the PC at High doesn't push High onto an iPad.

- A look is **self-contained**. Any key missing from it (an older look, or one written by hand) takes the default for this device when the look is applied. Applying the same look always gives the same picture, whatever was set before.
- Applying a look **replaces all playfield settings** (except cost), with Undo, as today.
- `applyLook` stays pure (settings in, settings out). Milestone 9.5 (playlists) needs to apply a look **temporarily**, as an overlay while a playlist plays, without writing the user's own settings. Design for that now, but don't build it.
- Each look has a **stable id** (a UUID, and fixed ids for built-ins such as `builtin:classic`). Playlists will refer to a look by id, not by name.
- Every look works for any use; there are no categories. The picker shows the built-ins in one list, then "My looks".
- A built-in that the user has changed shows as "<Name> · modified", as today. Built-ins can't be overwritten, only "Save as new…".

### Name, save, export, import

- **Save as new… / Save** (as today). Add **Rename**.
- **Export**: downloads one look as `<name>.pmlook.json`. **Export all my looks** downloads `pianomeister-looks.pmlook.json`. Export works for built-ins too.
- **Copy look** (from milestone 9's round 2, item 6) puts the same JSON on the clipboard. **Paste look** imports from the clipboard.
- **Import**: a file picker for `.pmlook.json`/`.json` (one look or many), or drag and drop onto the sidebar. Rules:
  - Validate like stored settings. Unknown keys are dropped. Out-of-range values are **clamped to the new ranges** (section B), with wrong types set to the default.
  - Run the settings migration if the file's version is older.
  - Cost keys in the file are ignored.
  - A name clash gives "Name (2)", "Name (3)", …, never an overwrite.
  - An id clash with an existing look gets a new id.
  - Import never applies a look. It adds the look to "My looks" with a toast: "Imported 3 looks · Apply 'Name'" (Apply only when there is exactly one).
  - A file that isn't a look file shows a clear error toast and changes nothing.
- Format:
  ```json
  {
    "format": "pianomeister-look",
    "version": 6,
    "looks": [
      { "id": "…", "name": "Synthwave",
        "createdAt": "2026-11-21T12:00:00Z", "settings": { "…": "…" } }
    ]
  }
  ```
- Saved looks are included in the **backup** export/import from milestone 7, with the same collision rules as the rest of the backup.
- Storage: keep looks device-wide. If that is currently localStorage, move them to Dexie (v6) so they sit beside playlists later. Migrate existing saved looks: old looks with only `LOOK_KEYS` get the rest from defaults, as the self-contained rule above says.

## B. Range testing and trimming

Goal: every slider's range covers only values that **make visual sense**. The ends should be "barely there" and "a lot", not "invisible" and "a white screen".

1. For **every numeric setting** in the playfield sidebar, render a contact sheet: the same frame at 7 values (min, the current default, and 5 points spread across the range, log-spaced where the effect is perceptual, such as size, strength, count and lifetime). Use the Pedal demo, paused on bar 2, `?animTime=3`, at 1280×720, with the default look. For effects that need motion (onsets, sustain effects, pulse), use a short playing capture at a fixed `animTime` sequence instead. Save the sheets to `test-results/visual/ranges/<section>/<key>.png`, each with a label strip showing the value under every frame.
2. Look at every sheet yourself. For each setting, find:
   - where it **stops being visible or distinguishable** (the useful minimum);
   - where it **saturates, clips, overlaps, becomes unreadable, or hides the notes** (the useful maximum);
   - for counts, lifetimes and sizes of particles, where it **hits the particle budget** at Medium in the dense-chord test, so the budget truncates it.
   - Allow a little headroom beyond "pretty", because some looks are meant to be loud. The ends should still look intentional.
3. Check the **pairs that interact** together, on a 4×4 grid each: bloom strength × threshold, bloom strength × radius, edge glow width × intensity, onset count × lifetime, sustain effect rate × lifetime, vignette × the dark highway colour.
4. Write `docs/design/m9-1/ranges.md`, a table with: section, key, old min/max/step, new min/max/step, default, and one line on why. Also list any setting whose step makes neighbouring values look identical; make the step coarser there.
5. **Stop and send me the table plus a zip of the contact sheets** before changing the registry. I'll approve the ranges.
6. After approval:
   - Update the registry.
   - The v6 load and look import **clamp** stored values into the new ranges (no version bump needed, since clamping is already part of validation; add a unit test).
   - Defaults and every built-in look must sit inside the ranges (unit test over `BUILT_IN_LOOKS`).
   - Sliders whose range is now mostly perceptual use a log scale where you used log spacing in step 1.

Do section B **before** finalising the built-in looks' numbers (section C), so the looks use the trimmed ranges.

## C. Built-in looks

Classic stays frozen (the milestone 8 picture). Below are the other thirteen, in picker order. The descriptions give the intent. Where a value is named, use it. Where a named option isn't a setting, use the closest one there is and list the substitutions in the report.

"Strong / medium / subtle" mean roughly 80 % / 50 % / 20 % of the **trimmed** range. Every look keeps the default camera unless stated, because changing someone's camera when they pick a look is surprising.

Every look must still read well at quality **Off** (no bloom). Bloom adds to a look; a look must not depend on it. Visual test: each look at Off and at Medium.

1. **Classic**: unchanged.
2. **Study**: for learning notes.
   - Note names on **both** (on notes and under keys), octave on C.
   - Octave lines B/C **and** E/F on, as subtle glowing lines. Highway borders on.
   - Solid heads and solid sustains, edge glow subtle.
   - Thin now line, White.
   - No onset effects, no sustain effect. Pulse subtle; sounding glow on, breathing off. Key spill off.
   - Bloom subtle.
3. **Night Focus**: the least distracting look, for long sessions.
   - Highway very dark `#05060A`, lanes barely visible, vignette strong.
   - Gradient sustains (dim tail), solid heads.
   - Glowing now line in Primary `#8AB4FF`.
   - No onsets, no sustain effect. Sounding glow subtle; pulse off.
   - Bloom subtle with a high threshold, so only the now line and the sounding notes glow.
4. **Blueprint**: a showcase for edge glow.
   - Highway `#07101F`.
   - Glass fill on heads and sustains at very low fill opacity, with a **strong** edge glow in `#6FA8FF`, so notes read as glowing outlines.
   - Bar lines visible, beat lines subtle. Borders and B/C octave lines glowing, `#6FA8FF`.
   - Thin now line, White. No onsets.
   - Pedal cage: border only, no fill.
   - Bloom medium.
5. **Neon**: Neon fill on heads and sustains. Neon now line in **Pitch** colour. Sparks. Borders glowing. Bloom strong.
6. **Ember**: Hot core heads, Gradient sustains. Embers sustain effect. Scaling sparks. Warm now line, Custom `#FFB46B`. Key spill on. Bloom medium.
7. **Crystal**: Glass heads and sustains. Glitter onsets. Cool lines in Primary. Key cones on. Bloom medium, low threshold.
8. **Aurora**: Gradient heads and sustains. Smoke sustain effect. Glow in Secondary `#7EE0C3`. Neon now line in Secondary. Breathing on. Bloom wide radius, medium strength.
9. **Synthwave**:
   - Highway `#0A0612`. Highway borders glowing `#FF4FD8`; octave lines glowing `#4FE3FF`.
   - Neon heads; **Diagonal stripes** on sustains.
   - Neon now line, Custom `#FF4FD8`. Scaling sparks.
   - Pedal cage: stripes fill, border `#4FE3FF`.
   - Key cones on. Bloom strong.
10. **Inferno**: the loudest fire look.
    - Hot core heads, Hot core sustains.
    - **Flame burst** onsets and **Flames** sustain effect.
    - Now line Neon, Custom `#FF8A3D`.
    - Key spill strong and key cones on. Pulse strong.
    - Bloom strong. Vignette medium.
11. **Stardust**: quiet sparkle.
    - Highway `#04040A`.
    - Glass heads, Gradient sustains in `#E9E4FF`-ish light.
    - **Glitter** onsets. Sustain glow. Sounding glow and breathing on.
    - Glowing now line in Pitch.
    - Bloom medium, low threshold, wide radius.
12. **Mist**: dreamy and soft; a showcase for smoke.
    - Soft Gradient heads, **Smoke** fill on sustains.
    - **Smoke** sustain effect. No lines except a thin now line, `#B8C7E0`.
    - Pedal cage: Smoke fill.
    - Bloom wide radius, low strength.
13. **Fireworks**:
    - **Explosion** onsets, count strong. Glitter is not combined, so the explosion reads on its own.
    - Neon heads, Solid sustains, all in Pitch colour.
    - Pulse strong. Glowing now line, White.
    - Bloom strong. Camera: a little more look-ahead than default (the one exception to the camera rule), so bursts have room.
14. **Hazard**: flat and graphic. It needs no bloom, so it's the best look on tablets and at Off.
    - Highway `#0B0B0D`.
    - **Diagonal stripes** on heads and sustains, in `#FFC21A` and `#141414`. Edge glow off.
    - Thin now line, White. Borders as plain lines.
    - Pedal cage: stripes `#FFC21A`/`#141414`, border `#FFC21A`.
    - No onsets, no sustain effect. Bloom off (strength 0).

For each built-in look, add a visual test at 1280×720 (Off and Medium) and a contact sheet `test-results/visual/looks/all-looks.png`: every look on one page with its name, at Medium. Send me that sheet in the report. These are starting values. We'll adjust them in the tuning session.
