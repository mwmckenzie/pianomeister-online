# Milestone 7.5 — Shortcuts

Read CLAUDE.md, docs/brief.md and docs/roadmap.md first, then plan the following. Work on a branch (`feat/m7-5-shortcuts`), not `main`.

## Goal

Every keyboard command can be rebound in Settings → **Shortcuts**, built on the command registry from milestone 7 (`core/commands/`). Also: a few useful commands that had no key yet, a shortcut cheat sheet, and layout-aware key handling so shortcuts work and read correctly on non-US keyboards (e.g. German QWERTZ). No mockup: build it from the milestone 6 components and the settings-window patterns (rows, reset icons, tab dot, changed count, Undo toast).

## Decisions

1. **Where:** Settings → **Shortcuts** tab (shown from now on), grouped by scope: **Player**, **Lists** (picker, library, bookmark manager), **Dialogs**. Each row: command label, its key chips, an "add" button, and the reset icon (dim at default, primary when changed — same as settings).
2. **Up to two keys per command.** Click a chip to re-record it; each chip has a small remove (×) on hover/focus; "+" adds a second key. A command may have no key at all (shown as "—"; it's then only reachable by mouse).
3. **Recording:** the chip switches to "Press a key…" with a hint "Esc to cancel". The next key press (with any Ctrl / Alt / Shift / Meta combination) becomes the binding. Modifier keys alone don't count; recording stops on blur.
4. **Reserved keys** can't be recorded; the chip shows why for a moment ("Esc is reserved for closing", "Tab moves focus", "Ctrl+W is used by the browser"). Reserved: Esc, Tab / Shift+Tab, and browser/OS combos (Ctrl/Meta + W, T, N, Q, R, L, Tab, F4, plus F5, F11, F12). Put the list in core with a test.
5. **Conflicts:** a key may be used once per scope. Player and Lists never run at the same time; Dialogs run on top of both, so a Dialogs key also conflicts with Player and Lists. On a conflict the row shows "Already used by ⟨command⟩" with **Replace** (moves the key to this command, leaving the other without it) and **Cancel**. Nothing is saved until resolved.
6. **Layout-aware matching:** printable characters without Ctrl/Alt/Meta are matched by the **character** (`KeyboardEvent.key`, case-insensitive), so "?" or "," works wherever that character is on the user's layout. Everything else (Space, arrows, Home/End, PageUp/Down, F-keys, Enter, and any combo with Ctrl/Alt/Meta) is matched by **physical key** (`KeyboardEvent.code`). Recording stores whichever applies. Migrate the existing defaults accordingly (letters, "," and "?" become character bindings).
7. **Key labels:** chips and every hint in the app (menu hints, tooltips, cheat sheet) show the effective binding: "Space", "←", "Home", "Ctrl+Shift+K", "?". For code bindings use `navigator.keyboard.getLayoutMap()` where available (Chromium) and a built-in US fallback elsewhere.
8. **Reset:** per command (reset icon), and "Reset all shortcuts" in the tab footer with the Undo toast; the footer shows "N shortcuts changed from default" and the tab gets the changed dot. Same patterns and components as the other settings tabs.
9. **Storage:** shortcuts are device-wide like the other settings: stored as overrides only (`{ commandId: Binding[] }`, absent = default) in the settings, schema **v5** with a migration (no overrides). Not part of the library backup.
10. **Binding type** is a tagged union (`{ kind: 'key', … }`) so milestone 11 can add `{ kind: 'midi', … }` for pedals and foot switches without changing the storage format.
11. **New commands** (bindable; defaults in brackets, all character-matched): **Tempo down / up** by the tempo step [`-` / `+`, also `=` for up], **Tempo to 100%** [`0`], **Loop on/off** [none], **Revert to bookmark** [none], **Show shortcuts** [`?`]. They behave exactly like the matching buttons (temporary changes with a bookmark loaded, etc.).
12. **Cheat sheet:** `?` (and a "Keyboard shortcuts" link in the Shortcuts tab and the left-menu hint area) opens a compact glass overlay listing every command with its current keys, grouped by scope, with a "Change shortcuts…" link to the tab. Esc or `?` closes it.
13. **Typing protection** stays exactly as it is: no player or list command fires while focus is in a text field, combo box or contenteditable. Recording mode itself captures keys before any command handling.

## Core (pure TS, unit-tested)

- `Binding`, `KeyBinding` (character or code + modifiers), `bindingFromEvent(event, mode)`, `matchesEvent(binding, event)`.
- `effectiveBindings(registry, overrides)`, `findConflicts(bindings, scope)`, `isReserved(binding)`, `formatBinding(binding, layoutMap?)`.
- `applyShortcutEdit(overrides, edit)` for record / remove / add / replace-on-conflict / reset / reset all (returns previous overrides for Undo).
- Registry: the new commands from decision 11; every command has a label and description for the cheat sheet. Keep the test that defaults don't conflict, now using `findConflicts` with the scope rules from decision 5.

## Tests

- **Unit:** matching by character vs code (incl. a German-layout case: "?" via Shift+ß, "-" key), modifiers, case-insensitivity; reserved keys; conflict rules across scopes; edits and Undo; settings v4 → v5; label formatting with and without a layout map.
- **E2e:**
  - rebind Play/pause to K → K plays, Space no longer does; reload → still K; reset icon → Space again;
  - add a second key; remove a key; a command with no key shows "—";
  - conflict → Replace moves the key; Cancel keeps both unchanged;
  - reserved key → refused with its message;
  - Esc cancels recording without closing the settings window;
  - Reset all + Undo;
  - new commands: tempo down/up/100% and Show shortcuts work; tempo keys respect the tempo step and the bookmark temporary layer;
  - typing in the picker search still triggers nothing;
  - menu hints and tooltips show the new key after a rebind;
  - no console errors.
- **Visual:** Shortcuts tab (default, one changed, recording, conflict) and the cheat sheet, 1280×720 and 1024×768, Glacier.
