# Milestone 1 — Core: MIDI import, tempo map, bar map, transport

Read CLAUDE.md and docs/brief.md first, then plan the following. Work on a branch (`feat/m1-core`), not `main`.

## Goal

Everything needed to *play a song in time* — without sound or 3D yet. All of it lives in `src/core/` as pure TypeScript (no Vue, Three.js, DOM, or Web Audio imports) and is unit-tested in Node. A small debug page proves it works in the browser.

## Dependencies

- Add `@tonejs/midi` (MIDI parsing, and writing for synthetic test fixtures). No other new dependencies.

## Core modules (one exported type/class/function group per file, per CLAUDE.md)

1. **Song model + import** (`importMidi(bytes: Uint8Array): Song`)
   - `Song`: `id` (SHA-256 hex of the file bytes via `globalThis.crypto.subtle` — async is fine), title (from track names/meta, fallback to file name supplied by caller), `ppq`, notes, channels present (with note counts), file tempo events, file time-signature events, duration.
   - `Note`: `{ midi, channel, startTick, endTick, velocity }` (velocity 0–127). Ticks are the source of truth; seconds are derived.
   - Notes are grouped by **channel, not track** (track layout varies; see Musette-style synthetic fixture 2).
   - Drop zero-length notes; keep overlapping same-pitch notes as separate notes.
2. **TempoMap** — tick ↔ seconds conversion across tempo changes; default 120 BPM if none.
3. **Meter + BarMap**
   - Built from the file's time signatures (dedupe repeated identical events; default 4/4), **or** from a `MeterOverride { timeSignature: {numerator, denominator}, barOneStartTick }` which replaces the file's time signatures.
   - Anything before `barOneStartTick` is **bar 0** (pickup / lead-in). Without an override, bar 1 starts at tick 0.
   - API (names are suggestions): `barCount`, `barStartTick(bar)`, `barEndTick(bar)`, `tickToPosition(tick) → { bar, beat, beatFraction }`, `beatsPerBar(bar)`. Beat unit = the time signature's denominator for now (compound meters later).
   - A–B ranges are inclusive by bar: `1–3` = start of bar 1 to end of bar 3.
4. **HandAssignment** — `{ right: number[], left: number[] }`, default `{ right: [0], left: [1] }`. Produces the playable note list tagged with `hand`; unassigned channels are dropped (hidden and silent).
5. **Transport** (state machine, clock injected)
   - `Clock { now(): number }` in seconds. Tests use a fake clock; the browser uses `AudioContext.currentTime`.
   - State: `stopped | playing | paused`. Song position in **song seconds at 100% tempo** (may be negative during pre-roll).
   - Controls: `play()`, `pause()`, `stop()`, `setTempoPercent(p)` (clamp 25–200, re-anchors so position doesn't jump), `seekToBar(n)`, `nextBar()`, `prevBar()` (bar-start snapping; prevBar within the first ~half beat of a bar goes to the previous bar, like a media player's "previous track"), `setLoop({ startBar, endBar } | null)`, `setPreRoll({ beats, mode: 'muted' | 'quiet', metronome: boolean })`.
   - **Pre-roll:** when playback starts (play from stopped, seek while playing, each loop iteration), position starts `beats` beats before the target bar start, using the tempo at the target. Before tick 0, extrapolate with the first tempo.
   - **Loop:** reaching the end of `endBar` jumps to `startBar` minus pre-roll.
   - `update()` is called by the host (once per frame). It advances position from the clock and emits events on the **event bus**: `noteOn` / `noteOff` (with note + hand), `allNotesOff` (on seek, loop jump, pause, stop), `beat` (bar, beat, isPreRoll — for the metronome later), `stateChange`, `loopWrap`.
   - Expose a pure query `notesStartingIn(fromSec, toSec)` and the current clock↔song mapping, so milestone 2's audio scheduler can schedule ahead of time.
   - Events during pre-roll carry `isPreRoll: true` so audio can mute/quieten them later.
6. **EventBus** — tiny typed pub/sub (`on`, `off`, `emit`). No external library.

`PracticeConfig` (from the brief's data model) can be defined as a type now, even though mute/solo is applied in milestone 2.

## Debug page

Route `#/debug` (not linked from the home page; fine to ship).

- Dropdown to pick one of the three fixtures (import them with Vite `?url`).
- File facts: format, ppq, tracks, channels with note counts, tempo and time-signature events, duration, bar count.
- Meter override inputs (time signature + bar-1 start tick) and hand channel assignment inputs.
- Transport controls: play/pause/stop, tempo % slider, prev/next bar, go-to-bar input, loop start/end bar, pre-roll beats + mode + metronome toggle.
- Live readout (updates each animation frame): state, song time, `bar:beat`, tempo %, and the currently sounding notes per hand (note names via the pitch-class module).
- Plain, functional styling — this is a developer tool.

## Tests

- Unit tests for every module above, against both the real fixtures (facts in the table) and the synthetic ones.
- Transport tests with a fake clock: tempo change mid-play doesn't jump position; seek emits `allNotesOff`; loop wraps at the end of `endBar` and re-applies pre-roll; pre-roll before bar 1 yields negative song time with no note events; pause/resume preserves position.
- Playwright: open `#/debug`, select the Minuet, assert bar count 64; press play, wait ~1 s, assert the readout shows bar ≥ 1 and state `playing`.
