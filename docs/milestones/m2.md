## Core additions (pure TS, unit-tested in Node)

1. **Pedal import:** extend `importMidi` to read CC64 per channel into `PedalInterval[]` on `Song` (down at value ≥ 64, up below; an unterminated pedal ends at song end; ignore repeated "down" while already down).
2. **Sounding length:** a pure function that computes each note's `soundEndTick` = its `endTick`, extended to the pedal-up tick if the note ends while its channel's pedal is down, but cut at the next onset of the same pitch on the same channel. Visual `endTick` stays unchanged.
3. **Beat query:** `beatsStartingIn(fromSec, toSec)` on the transport (like `notesStartingIn`), returning `{ bar, beat, isDownbeat, isPreRoll, songSec }` — for the metronome scheduler.
4. Synthetic test fixtures (built in tests): pedal down/up spanning several notes; re-struck pitch under pedal; pedal on one channel only (other hand unaffected); unterminated pedal.

## Audio layer (`src/audio/`)

- **AudioOutput interface** (what the scheduler talks to): start a note at an audio time with velocity, gain group (right / left), and duration; stop all; set group gains. One implementation uses smplr; a **recording fake** is used in unit tests so the scheduler is testable in Node without Web Audio.
- **Per-hand volume without loading the samples twice.** Investigate how smplr can route notes to two gain groups (e.g. per-note destination, two instruments sharing decoded buffers, or smplr's lower-level sampler with shared buffers). If none works cleanly, propose the alternative in the plan before building — don't double sample memory, and don't fake volume via velocity (that changes timbre, not just loudness).
- **Gain structure:** master gain → per-hand gains (volume × mute/solo) → and a pre-roll multiplier (0 for muted, 0.25 default for quiet) applied to notes flagged `isPreRoll`.
- **Scheduler:** a look-ahead loop (e.g. tick every 25 ms, schedule window ~100 ms ahead) using `notesStartingIn` / `beatsStartingIn` and the transport's clock↔song mapping. Note start in audio time = mapped song time; duration = sounding length scaled by tempo rate.
  - **Loops:** notes at the loop start must play on time, with no gap or double-trigger at the wrap. Design how the scheduler sees across the loop boundary (e.g. the transport exposes the upcoming timeline segment(s) including the wrap). Cover it with tests.
  - **Seek / pause / stop / tempo change / allNotesOff:** cancel notes scheduled but not yet started, release sounding ones quickly (short fade, no clicks), and reschedule from the new position.
  - **Background tabs:** `requestAnimationFrame` stops when the tab is hidden. Playback (audio and transport state) must keep going correctly; make sure transport updates don't depend only on rAF.
- **Metronome:** synthesized click (oscillator + short envelope), higher/louder on downbeats. Modes off / pre-roll only / always; own volume. Scheduled through the same look-ahead.
- **Velocity:** pass MIDI velocity (0–127) to smplr's velocity so the right velocity layer is used.
- **Loading & unlock:** expose a loading state (progress if smplr provides it). The AudioContext is resumed on the first user gesture; Play is disabled until samples are loaded.
