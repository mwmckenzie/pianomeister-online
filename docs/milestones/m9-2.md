# Milestone 9.2 — Practice clarity: loop visibility, black notes, keyboard, small fixes

Added 2026-11-22. Builds on milestones 9 and 9.1. Branch: `feat/m9-2-practice-clarity`, from `main` after 9.1 is merged.

Every new setting follows the usual rules:

- a reset icon;
- part of looks;
- clamped on load and import;
- a disabled hint where a rule applies;
- unit tests.

New playfield settings enter the 9.1 range format (min, max, step, linear or log). Pick sensible ranges and check them on a contact sheet. Classic and the other built-in looks pin their values explicitly, so adding a setting never changes how an existing look appears.

## A. Loop visibility on the highway

Problem: while practising, the loop ending and resetting is a surprise.

1. **Dim outside the loop.** While a loop is active, everything on the highway outside it (notes, lanes, lines and effects before the loop start and after the loop end) is covered by an overlay in the highway background colour.
   - Settings: "Dim outside the loop" (on/off, default on) and "Dim strength" (default about 60 %).
   - Nothing changes when no loop is active.
   - The keyboard is never dimmed.
2. **Loop boundary lines.** A line across the highway at the loop start and at the loop end, so the end is visible well before it arrives.
   - Settings: on/off (default on), colour (default Secondary), width, glow. They use the same line renderer and glow as the other highway lines.
   - The lines never hide notes: they draw under note heads.
3. **After the loop end.** Setting "After the loop end": **Next repeat** (default) / **Song continues**.
   - **Next repeat:** beyond the loop-end line the highway shows the loop's start again: the notes you will actually play next, including the pre-roll gap if the loop has one. This repeats as far as the look-ahead reaches, so a short loop can appear several times. These notes are not dimmed; the boundary line marks each seam.
   - **Song continues:** beyond the loop end the song continues as today, dimmed by item 1.
   - Both modes keep timing exact. The repeat is placed at the time it will actually play, including any count-in or pre-roll the loop uses.
4. **Edge cases:**
   - A loop shorter than the look-ahead.
   - A loop starting at bar 1.
   - Loop on and off while playing, and seeking while paused: no flash, no one-frame glitch.
   - Bookmark loops and the Loop editor's ranges behave the same.
5. **Performance:** the repeat must not duplicate the song's note geometry on the CPU each frame. Draw the loop range again with a time offset (or instance it) and measure. Report draw calls before and after.

## B. Black notes back on the highway

Problem: lifting black-key notes off the highway makes them look later than they are on a tilted camera (parallax), and the more tilt, the bigger the error. Shadows don't fix it on dark, bloomed or low-resolution scenes; the 9.1 low-camera pass showed shadow strength has no visible effect on the default highway.

1. **Black notes sit on the highway.** Where they overlap white notes, they always draw above them, by explicit draw order (not by depth alone), with only a tiny world lift as a safety margin. No z-fighting at any distance or camera.
2. **Remove "black-key note lift"** (`notes.blackLift`). Migrate stored settings, looks and look files (a settings version bump).
3. **Separate head heights:** "White note height" and "Black note height". The default black height is taller than white. The front edge always starts on the highway, so timing is read where the note touches it. Range-test both at 25° and 85° tilt; heights where the top face dominates at high tilt are out of range.
4. **Optional raised black sustains:** "Raised black sustains" (default off) plus "Ridge height". The sustain becomes a low ridge with a flat top and square ends, the same shape as a 3D head but lower. Keep the height range low: range-test the point where releases start to look late, and make that the maximum.
5. **Darker side faces** on 3D black heads, so they read as solid blocks when shadows are lost.
6. **Shadow strength:** re-check it once black notes are back on the highway. If it still has no visible effect on the default highway, propose whether to keep, rework or remove it, and stop for my decision.
7. Black lanes are already narrower; no change to sustain width.

## C. Deeper black keys on the keyboard

Problem: when a white key is pressed, the bottoms of the neighbouring black keys show.

1. Black keys extend below the surface at least as deep as the white keys, so their bottoms never show: not with any white key pressed, not with the black key itself pressed, and not at any camera tilt in the allowed range.
2. The newly visible side faces use the black key's normal side shading, with no lighter or mismatched faces. Key light spill, cones and pressed overlays still look right on them.
3. `keyboard.pressDepthBlack`: re-check its range now that the geometry changed (9.1 left it for this milestone).

## D. Open on Home at the start of a new session

1. When a new session starts, the app switches to the Home/Welcome page. That includes on load, refresh and refocus, but **only when the session rules already used by the stats say a new session has begun**, not on every refresh or refocus.
2. Setting in Settings → Home/Welcome: "Open Home when a new session starts" (default on), with a reset icon like every setting.
3. **It never interrupts.** Not while a song is playing, and not while there's an unsaved draft or an open dialog (for example a bookmark draft). In those cases it waits until the next new session.
4. E2e: simulate a new session (clock or idle gap per the session rules) and check that the app opens Home; check it does not open Home during playback or with a draft open; check the setting turns it off.

## E. Change song and Library open on the current song

1. Opening the Change song picker or the Library highlights and selects the current song, and the current bookmark if there is one, and scrolls both into view, whatever sort order is active.
2. If an active search or filter hides the current song, don't clear it silently. Show a small line, "Current song is hidden by the filter · Show", that clears the filter and reveals the song.
3. Keyboard focus starts on the selected song, so the list keys continue from there.
4. E2e: with each sort order, open the picker and check the current song is selected and visible; then the same with a filter that hides it, using the "Show" line.
