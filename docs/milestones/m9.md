# Milestone 9 — Visual polish (glow, lines, note styles, effects)

Read CLAUDE.md, docs/brief.md and docs/roadmap.md first, then plan the following. Work on a branch (`feat/m9-visual-polish`), not `main`.

## Goal

Enhance the design we already have — not replace it — with light: glowing important lines, glowing note edges and cage borders, shader fills for notes and cages, pulses on note-on, glow while notes sound, and richer effects at the now line. **Everything is an option**: each effect can be turned on/off, tuned, and swapped for an alternative, live from the playfield sidebar. Backgrounds go **very dark** so the light reads. The defaults get tuned together in a session after the first build (like milestone 5).

References (inspiration only, not to copy): glowing pill notes with glitter sparks; neon outlined notes with a flaming now line and light cones onto keys; ember/lava cores with drifting embers; glassy notes with glowing lane pillars and low mist; gradient notes; note names on notes and under keys.

## Decisions

### Rendering

1. **Selective bloom**: only elements flagged as emissive glow — lines from decision 3, note edges, cage borders, lit key overlays, pulses, now-line effects. The rest of the scene (highway surface, unlit keys, sustain fills unless their style is emissive) does not bloom. Settings: bloom strength, radius, threshold. Use what ships with `three` (EffectComposer / bloom pass, layers or a mask) — no new dependencies.
2. **Quality presets** under Render quality: **Off / Low / Medium / High** (bloom resolution and passes, particle budget, shader detail). Default **Medium** on desktop, **Low** on tablets (touch + small screen). Each preset is a starting point; individual settings stay tweakable.
3. **Glowing lines** (each: on/off, colour, width, glow intensity):
   - **Now line** — styles: thin, glowing, neon (bright core + wide soft halo), gradient across the width using the pitch colours of the keys underneath;
   - **Highway borders** (left/right edges);
   - **Octave markers**: a line on every **B/C boundary** (option: also E/F) running up the highway;
   - existing bar/beat lines can opt into a faint glow.
   Colour options per line: white, primary, secondary, or pitch-derived (now line).
4. **Very dark defaults**: darken the background and highway surface further (e.g. near-black blue) and add an optional subtle vignette, so lighting carries. Update brief decision 22's defaults after tuning.

### Notes

5. **Edge glow** on notes (heads and sustains): a rim/outline that blooms; thickness and intensity; follows the note's perspective and taper (never screen-aligned), and its size stays constant in world units (like milestone 5's bevel).
6. **Note fill styles** (shader backgrounds for the note area), chosen separately for **heads** and **sustains**:
   - Solid (today), Gradient along the length (head → tail, colour and/or brightness), Hot core (ember/lava: bright centre, darker edges, subtle flicker), Glass (translucent with highlights), Neon (hollow: edge only), **Diagonal stripes** (fat stripes in the note colour, optional slow scroll with the music), Smoke/noise (soft animated texture).
   - All patterns are computed in each note's own highway coordinates so they move and taper with the note, never screen-aligned.
7. **Note-on pulse**: a short bloom flash on the key's colour overlay **and** on the whole note at the moment it starts — amount, decay (ms), velocity-scaled (reuse milestone 5's velocity scaling).
8. **Sustain glow**: notes that are currently sounding glow brighter (fill and edge), with an optional gentle breathing pulse.
9. **Note names**: off / on notes / under the keys / both. Letter names with the octave on every C (C4) or on all notes (option); sharps or flats (♯/♭ option). Names on notes show only when the head is large enough to read; always in a legible light text with a dark outline. (Colour-by-hand is **not** added — hands get their own treatment through hand cages in milestone 10.)

### Cages (regions on the highway)

10. A generic **cage renderer**: a region on the highway defined by a tick range × key range (or full width), with a **border** (glow, width, colour, corner rounding) and a **fill** using the same style list as notes (decision 6 — incl. stripes, smoke, gradient) at a chosen opacity. Drawn under the notes, perspective-correct.
11. **Pedal sections** move onto it: today's pedal shading becomes a pedal cage (full width while the sustain pedal is down) with its own border/fill options; today's look stays available as the default style.
12. Milestone 10's **hand cages** will reuse this renderer, so design its API for per-hand regions that change per bar (no hand-cage logic now).

### Now-line effects

13. **On note-on** (choose one or combine): sparks (today), scaling sparks (start big, shrink), flame burst, explosion (flash ring + debris), glitter puff. Each: size, count, lifetime, spread, velocity scaling, coloured by pitch.
14. **While a note sustains** (at the now line): none, glow (today's held glow), embers (small particles drifting up), small flames, smoke wisps. Same tuning knobs.
15. **Key light**: lit keys can spill a soft coloured light onto neighbouring keys and, optionally, a light cone down the key toward the player (strength, spread).
16. A global **particle budget** per quality preset; under heavy load the oldest particles go first. Reduced motion: no flicker/breathing/scrolling animations, effects become short fades.

### Settings and looks

17. All of this lives in the **playfield sidebar** (live on the highway): new/extended sections **Lines & glow**, **Note style**, **Effects** (now-line, pulses, sustain), **Pedal & cages**, **Note names**; bloom and quality in **Render quality**. Every control has its reset icon; sections and the sidebar keep their reset buttons. Settings schema bump with migration.
18. **Looks** (swappable combinations): "Save current look…" stores all visual settings under a name; a **Look** picker at the top of the sidebar switches between saved looks and a few built-in ones created in the tuning session (e.g. Classic = today's look). Picking a look applies all its values (Undo toast); tweaking afterwards shows "⟨Look⟩ · modified" with "Save" / "Save as new". Looks are device-wide like settings, not in the library backup.

## Process

1. Build decisions 1–17 with **provisional defaults** (close to today's look, glow subtle), plus the Looks mechanism (18) with only "Classic".
2. **Tuning session**: I try combinations live in the sidebar; we record the values for the defaults and 3–5 built-in looks.
3. Lock defaults and built-in looks; update the brief.

## Tests

- **Unit:** settings registry entries and migration; looks (save, apply, modified detection, Undo); note-name formatting (sharps/flats, octave rules); particle budget logic; cage region math (tick/key range → highway quad).
- **E2e:** every new sidebar control changes the scene without console errors; quality presets switch; looks save/apply/modified/Undo; note names on/off; reduced motion disables animated effects.
- **Visual:** a fixed frame (fake clock, paused mid-chord with a sustain and the pedal down) for: today's look, all effects off, each note fill style, each now-line style, glowing octave/border lines, pedal cage styles, note names, each quality preset — 1280×720, plus a few at 1024×768.
- **Perf:** frame time at Off / Low / Medium / High on Canon and the 340-bar fixture with a dense chord section; High must stay within the frame budget on this machine, Low must stay close to today's numbers.

## Done when

`npm run check`, `npm run build`, `npm run test:e2e` (preview, no retries), `npm run test:perf` and the visual shots pass. Report in `docs/reports/feat-m9-visual-polish.md` with screenshots listed, perf numbers per quality preset, open questions and a manual checklist; stop for my review (and the tuning session) before committing.
