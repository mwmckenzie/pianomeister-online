# Milestone 10.6 — Note colour set editor

Added 2026-11-25. Branch: `feat/m10-6-colour-sets`, from `main` (10.5 merged).

## Goal

Let the player change the note colours. They can edit a built-in set (with a reset per colour and for the whole set), or make, rename, duplicate and delete sets of their own. A live preview shows the result. Looks that use a set keep working on another device and after the set is deleted.

Mockup: `docs/design/m10-6/source/QGColourSets.dc.html` (Settings → Appearance).

## Today (check and correct in the plan)

- Note colours come from a palette chosen per look: Default, Warm, Cool, Neon, Pastel, Mono or Two-tone (`Note colours` in the look's settings).
- Notes are coloured by pitch class, which the mockup assumes means 12 colours per set. If a palette is built differently (for example Two-tone from white and black keys, or Mono from one colour), say so in the plan and propose how the editor shows it. The default answer is that every set is stored as 12 colours, with the built-ins expanded to 12.

## Definitions

- **Set:** an id, a name and 12 colours (hex, `#rrggbb`), indexed by pitch class C = 0 … B = 11.
- **Built-in set:** one of the 7 shipped sets. It can't be renamed or deleted. Its colours can be changed: each change is stored as an override (pitch class → colour) on top of the shipped colours. A built-in with at least one override is **modified**.
- **Custom set:** made by the player, with its own name and 12 stored colours (no overrides).

## Storage

- Overrides and custom sets are **app settings** (not look keys), under a new `noteColourSets` key: `{ overrides: { [builtinId]: { [pitchClass]: hex } }, custom: [{ id, name, colours }] }`.
  - Custom ids are `custom-` plus a random id.
  - Bump the settings version, with migration (empty).
  - Say in the plan whether app settings are per profile today. They should follow whatever the other appearance settings do.
- **Backups:** include `noteColourSets` (bump the backup format if needed).
- **Looks:** a look stores the set id it uses **and a snapshot of the 12 colours**. This applies to built-in, custom, exported (`.json`) and playlist looks.
  - If the set exists, the look follows the set's current colours, so editing a set updates every look that uses it, built-in looks included.
  - If the set is missing (deleted, or on another device), the look uses its snapshot. The look's Note colours select then shows "⟨name⟩ (saved in look)", plus an action "Save as a set", which adds it as a custom set.
  - The snapshot is refreshed whenever the look is saved.
  - Older looks have no snapshot and only reference a built-in: nothing to migrate.

## Settings → Appearance: "Note colours" (mockup QGColourSets)

Three columns.

**Sets list (left)**
- "Built-in" lists the 7 sets in their current order; "Your sets" lists custom sets, newest last.
- Each row has a strip of its 12 colours and its name. A modified built-in shows "· modified" in the warning colour (`--warning`, `#E9C07A`).
- "+ New set from current" makes a custom set from the selected set's current colours, named "⟨name⟩ copy" (with " 2", " 3" and so on if taken), and selects it with its name field focused and selected.
- Selecting a set here **only selects it for editing**. Which set the playfield uses is still chosen in the look (unchanged).

**Editor (middle)**
- **Name:** read-only for built-ins, with the label "Built-in set (edit colours here, or duplicate to make your own)". Editable for custom sets; it saves on blur or Enter. An empty name reverts.
- **Buttons:** **Duplicate** (as "+ New set from current"). **Delete** (custom only) asks "Delete ⟨name⟩? Looks that use it keep their colours." with Delete and Cancel. **Reset all colours** (modified built-ins only).
- **Keys:** one octave of keys, C to B, each showing its colour in a swatch. Click a key, or use Tab and arrow keys, to select it. A modified colour has an amber ring around its swatch. Above the keys: "N colours changed from the original" or "Original colours" (built-ins only).
- **Selected colour:** a large swatch, the note name, "modified · was #xxxxxx" when changed, a native colour picker, a hex field (accepts `#rrggbb` or `rrggbb`, case-insensitive, and reverts on anything else), and **Reset this colour** (built-ins, enabled when modified).
- **Changes apply at once** and save as you go. Picking a built-in's original colour removes that override.
- **Warning:** when two neighbouring pitch classes (including B and C) differ by less than 8 in OKLab ΔE (×100) but aren't identical, show "Hard to tell apart: C and C♯, … Neighbouring notes may look the same on the highway." List up to 3 pairs, then "and N more". Identical colours never warn, so Mono and Two-tone stay quiet. It's advice only and blocks nothing. Put the ΔE function in core with tests.
- **Bottom:**
  - On a modified built-in: **Save as new set…**, which makes a custom set from its current colours and asks for a name.
  - A footer line: "Changes apply now and can be reset per colour." (built-in), "Changes apply now. Save as a new set to keep the original too." (modified built-in), or "Changes save as you go." (custom).

**Preview (right)**
- A small highway with falling notes over two octaves, coloured by the selected set. It also follows the look's fill style if that's cheap; otherwise solid.
- If the playfield is visible behind Settings and uses the edited set, it updates live too.
- The text under the preview: "A look that uses this set stores its colours, so the look still works on another device or after you delete the set."

**Look's Note colours select**
- It lists the built-ins (with "· modified"), then the custom sets, then any "(saved in look)" entry.
- A shortcut "Edit colours…" opens this page with that set selected.

## Reset rules (everything configurable has a reset)

- Per colour: **Reset this colour**.
- Per built-in set: **Reset all colours**.
- The Appearance tab's existing "Reset to defaults" (if there is one) also clears all built-in overrides. It never deletes custom sets. Confirm with "Reset appearance? Your own colour sets are kept."

## Tests

- **Unit:**
  - set resolution: override over built-in; look snapshot when the set is missing;
  - name collision on copy;
  - hex parsing;
  - ΔE and the warning rule (identical pairs ignored, B–C wraps);
  - settings migration;
  - backup round trip with custom sets;
  - a look export/import carrying the snapshot.
- **E2e, new tag `@colours`:**
  - change a built-in colour: the swatch, "· modified", and the highway note colour (pixel check on one note, as `@cages` does, if cheap);
  - reset it;
  - make, rename and delete a custom set, where a look using the deleted set keeps its colours and shows "(saved in look)";
  - reload, and everything persists.
- Follow CLAUDE.md: related unit tests plus `npm run test:e2e:affected` (add `@colours` to the e2e-affected map); no full suite.

## Acceptance criteria

1. Every built-in colour can be changed and reset, one at a time or all at once.
2. Custom sets can be made, renamed, duplicated and deleted, and survive reload, backup and restore.
3. Looks using a deleted or missing set keep their colours.
4. The preview and the highway update immediately.
5. The warning shows for close neighbours only, never for identical colours.
6. `npm run check` passes; `test:e2e:affected` passes, including `@colours` and `@smoke`.

## Not in this milestone

- Colour sets beyond pitch class (per hand, per velocity).
- Import or export of a single set as a file.
- Colour-blind simulation in the preview.
