# Milestone 7 — Profiles, bookmarks, stats

Read CLAUDE.md, docs/brief.md and docs/roadmap.md first, then plan the following. Work on a branch (`feat/m7-profiles-bookmarks-stats`), not `main`.

## Goal

Make practice remembered. Local profiles; bookmarks as saved practice setups; a raw play log with stats computed from it; and the screens that were designed in milestone 6 but left without data: the picker's stats and bookmark list, the library's practice columns, and the bookmark manager page. References: `docs/design/m6/source/QGPicker.dc.html`, `QGLibrary.dc.html`, `QGBookmarks.dc.html` (sizes, spacing, columns), built with the milestone 6 components and tokens.

## Decisions

1. **Profiles.** Local to the browser (brief 4). Each profile has a name and a colour (picked from the five theme preset primaries). First run creates one profile, "Me", silently — with a single profile nothing about profiles is shown in the player.
2. **What belongs to a profile:** bookmarks, play log and sessions, per-song hand assignments (brief 6), and the last opened song/bookmark. **Settings stay device-wide** in this milestone (playfield, audio, appearance are shared by all profiles). Songs, metadata edits and meter overrides stay shared (brief 3, 6).
3. **Switching profiles:**
   - Settings → **Profiles** tab: list with name, colour, total practice time and last practiced; create, rename, recolour, switch, delete (confirm dialog naming what is deleted: its bookmarks and stats; the last profile can't be deleted).
   - When there are **two or more** profiles, the player's left menu gets a fifth item at the bottom: a small circle in the profile colour with the initial (same dim/hover behaviour as the other icons); clicking it opens a compact profile switcher popover. Shortcut: none.
   - Switching stops playback, reloads the profile's last song/bookmark, and shows a toast "Switched to ⟨name⟩".
4. **Bookmarks** (brief data model `Bookmark` + `PracticeConfig`, limited by decision 61): a bookmark stores name, song, bar range (start ≤ end), tempo %, per-hand mode (on / muted / solo), pre-roll beats and pre-roll mode, and (from review round 3) the metronome mode (off / pre-roll / always). It does **not** store hand-channel assignments (those are per song per profile) or volumes, the metronome's included (global).
5. **"Full song"** is tracked like a bookmark for stats (id `full:<songId>`), always exists for every song, can't be edited, renamed or deleted, and loads with no overrides: whole song, tempo 100%, hands on, pre-roll from the Practice settings. It shows first in the picker's Load list; the bookmark manager doesn't list it (review round 3).
6. **Loading** a bookmark applies its loop (on), tempo, hand modes and pre-roll; the HUD shows the bookmark name on its own line under the composer ("Full song", dimmed, when none is loaded). **Bookmarks are edited only in the bookmark manager, never from the player screen.** While a bookmark is loaded, player-side changes (loop range, tempo, pre-roll in the loop popover, hand On/Mute/Solo in the Audio tab) are **temporary**: they apply immediately but never write to the bookmark or to the global settings, and they are dropped when another song or bookmark is loaded (no prompt). Those controls show a short note "Temporary for ⟨bookmark⟩ · edit it in the Bookmark manager" (the latter a link that opens the manager with that bookmark selected); their reset icons go back to the bookmark's saved value. The HUD shows a small dot after the bookmark name while any temporary change is active; the loop popover offers **Revert to bookmark** to drop them all. **Save as bookmark** only ever creates a new bookmark from the current setup (decision 7). With Full song loaded, those controls edit the global settings as before.
7. **Creating bookmarks** (revised in review round 3):
   - In the player only: a save-bookmark icon in the right column below the loop and tempo rows (hint "Save as bookmark B", shortcut `B`), and **Save as bookmark** in the loop popover — the same one-click action. It saves the song, loop range (or the whole song), tempo, hand modes and pre-roll with the automatic name, makes it the loaded bookmark and shows "Saved "⟨name⟩"" with Rename (opens the manager with the name focused) and Undo. No dialog. If the profile already has a bookmark with the same settings, nothing is created: that one is loaded and the toast says "Already saved as "⟨name⟩" · no new bookmark created" with Show.
   - **Automatic names:** the full summary, e.g. "Bars 1–4 · 100% · both hands · pre-roll 2". While a bookmark's name is automatic it follows its settings; typing a name makes it custom; the name field's reset makes it automatic again. Lists show the summary under a name only when it's custom.
   - No **New bookmark** in the manager. **Duplicate** makes a draft that lives only in memory until an edit makes its settings differ from every bookmark; leaving it unchanged asks "Discard this duplicate?". Delete shows the Undo toast instead of a confirm.
8. **What counts as a play and as practice time:**
   - **Practice time** = time the transport is actually playing (brief 5), including pre-roll, attributed to the loaded bookmark or Full song.
   - **A play** = one **complete pass**: the loop wraps (each iteration counts) or the song reaches its end. Partial passes add time but not plays.
   - **Raw log:** one `PlayRecord` per playback stretch (start → pause/stop/song change/tab hidden), holding `profileId, sessionId, songId, bookmarkId, startedAt, playedMs, passes`. Stats are always computed from the log (brief), never stored as counters.
   - **Sessions** as brief 5: start on first playback, end after 10 minutes without playback or when the app closes (end time = last playback).
   - Records are written on every stretch end and also every 30 s while playing, so a crash or closed tab loses at most 30 s.
9. **Stats shown** (all per active profile):
   - **Song:** plays (sum over Full song + its bookmarks), practice time, last practiced, bookmark count.
   - **Bookmark / Full song:** plays, practice time, last practiced, share of the song's practice time.
   - **14-day chart:** practice minutes per local calendar day, today's bar in primary; for the song and for the selected entry.
   - **Profile summary** (Profiles tab): total sessions, songs practiced, total practice time, most practiced song, last practice, average session length.
   - Formats: "14 min", "1 h 5 min", "—" for none; last practiced "Today", "Yesterday", "4 days", "10 Nov" (reuse `formatAddedAt` style).
10. **Deleting an upload** asks whether to also delete its bookmarks and stats; default **keep** (song identity is the content hash, so they come back if the file is uploaded again). Orphaned bookmarks of missing songs are hidden from lists, not deleted.
11. **Backup:** the milestone 4 library export/import gains profiles, bookmarks, hand assignments, sessions and play records (versioned format; older backups still import). Import **merges** by id (existing records are kept; nothing is overwritten); profiles with the same id merge. A summary toast reports what was added.

## Data

- Dexie **v3**: tables `profiles`, `bookmarks` (index `[profileId+songId]`), `sessions`, `playRecords` (indexes `[profileId+songId]`, `[profileId+bookmarkId]`, `[profileId+startedAt]`). The existing hand-assignment table gains `profileId`; the upgrade creates the "Me" profile and assigns all existing rows to it. Keep upgrades schema-only plus this one deterministic move; nothing that parses files.
- `appState`: active profile id; last opened song/bookmark becomes per profile.
- Repositories in `data/` for each table; all writes go through them.

## Core (pure TS, unit-tested)

- `core/practice/PracticeConfig` + `applyBookmark` / `diffFromBookmark` (for the modified dot).
- `core/stats/`:
  - `PlayRecorder`: a pure state machine fed with transport events (play, pause, stop, loop wrap, song end, song change, visibility hidden, tick every 30 s) → emits `PlayRecord` writes. Tested with synthetic event streams.
  - `sessionize` (10-minute gap rule), `songStats`, `bookmarkStats`, `profileSummary`, `dailyMinutes(records, days, timeZone)` (local days, DST-safe).
  - Sort comparators for plays / time / last / bookmarks (most/least, most recent first), shared by picker and library.

## Screens

1. **Song picker** (`QGPicker` source):
   - Song list columns: title + composer, bookmarks, plays, time, last — all sortable via the headers (click again to flip). Default sort: last practiced. Bars/Length move out of the list (they're in the facts).
   - Middle: facts as now (title, composer · source, Length, Bars, Meter "4/4+", Tempo, hands, range); then **song stats** (Played, Practice, Last) + 14-day chart; divider; **selected entry's stats** (name, "Bars 17–32 · 85% · left muted · pre-roll 2", Played, Practice, Share) + its chart. Full song is selected by default.
   - Right "Load" list: Full song pinned, then the song's bookmarks; each row shows name, bar range, range bar (secondary), plays, time, last; sortable by plays / time / last.
   - Footer: Library…, Cancel, **Load full song / Load bookmark**.
2. **Library:** table gains **Plays** and **Last** columns (sortable); row subtitle becomes the bookmark count ("2 bookmarks", nothing when none). Details panel gains a "Bookmarks" button that opens the bookmark manager filtered to the song. Header tab bar: **Library | Bookmarks**. New uploads get a guessed title and composer, and the details panel a **Guess from file** button next to Reset to original (brief decision 79, review round 3).
3. **Bookmark manager** (`QGBookmarks` source; route `#/bookmarks`):
   - Left: "All bookmarks" + one filter row per song that has bookmarks, with counts.
   - Middle: grouped by song (header "Minuet in G · 64 bars"); per group the bookmarks (no Full song row): name (+ summary when the name is custom), range bar, plays, time, last. Search filters names and song titles.
   - Right edit panel: name; bar range with the same two-thumb range slider + From/To fields as the loop popover; tempo slider; hand modes (right / left: On · Mute · Solo); pre-roll beats (inverted slider) and mode; stats (Played, Practice, Last) and 14-day chart; **Load in player**, Duplicate, Delete. Edits save on change; every field has its reset icon, which resets to the default for new bookmarks (the name's reset makes it automatic). Empty state: "No bookmarks yet. In the player, set up the loop, tempo and hands you want and press [icon] or B."
4. **Player:** the bookmark name (or "Full song", dimmed) on its own line under the composer (+ modified dot at its end); a Stop button before Previous bar; the save-bookmark icon below the tempo row; loop popover gains the temporary-change note, Revert to bookmark and Save as bookmark (decisions 6–7); every committed loop change moves the playhead to the loop start (brief decision 8); the left menu gets the profile item when there are 2+ profiles.
5. **Settings → Profiles tab:** profile list and actions (decision 3), and the active profile's summary stats (decision 9). The settings window's existing changed-count/reset footer doesn't apply here (no settings).

## Tests

- **Unit:** `PlayRecorder` (pause/resume, loop wraps count passes, song end, song change mid-pass, tab hidden, 30 s ticks, pre-roll time counted, no double counting); `sessionize`; stats and share; `dailyMinutes` across midnight and DST changes; sort comparators; bookmark apply/diff; Dexie v2→v3 upgrade (assignments moved to "Me"); backup v-old → v-new import and merge (no duplicates on re-import).
- **E2e** (use Playwright's fake clock for anything time-based):
  - save a loop as a bookmark from the popover → appears in picker and manager → load it → HUD shows the name, settings applied;
  - change tempo → modified dot → Revert → dot gone; saving the same settings again creates nothing;
  - every loop trigger (loop on, slider release, From/To, Revert, loading a bookmark) moves the playhead, playing and paused;
  - Duplicate: leave → Discard; edit → kept; Keep editing;
  - play two loop passes → picker shows 2 plays and the time; Full song stats separate;
  - edit a bookmark in the manager (range, hands) → load → applied; delete → Undo restores it;
  - the manager lists no Full song and has no New bookmark;
  - second profile: create, switch via Profiles tab and the menu item, bookmarks and stats are separate; delete profile with confirm;
  - export → clear storage → import → bookmarks and stats back; import twice → no duplicates;
  - picker/library sorting by plays, time, last, bookmarks;
  - no console errors.
- **Visual** (seed a deterministic play history through a test helper that writes IndexedDB — not shipped in the app): picker with stats (song + bookmark selected), library with practice columns, bookmark manager (bookmark selected, a draft duplicate), Profiles tab, HUD with a bookmark name and modified dot. 1280×720 and 1024×768, Glacier and Ember. Check them against the sources yourself.
