## Goal

The real player: a Three.js scene with a perspective note highway that runs straight into a true-to-scale 88-key keyboard, colored notes with sustains, key fade-ins, now-line effects, and pedal shading — driven by the m1 transport and m2 audio. The player becomes the home page, with a HUD and a settings panel. The debug page stays at `#/debug`.

- Add these under "Confirmed decisions", continuing the numbering (from **18**):
  - **Highway geometry:** look-ahead measured in quarter notes (ticks / ppq), default **8**, adjustable. Notes are drawn out to **1.5×** the look-ahead and fade in through a haze toward the horizon, so nothing pops in. Spacing is tempo-independent: slowing the tempo slows the scroll, not the spacing.
  - **Notes:** flat strips. **Head** = solid pitch color, length of a **1/64 note** (ppq/16 ticks), or the whole note if shorter. **Sustain** = the rest of the note, full lane width, translucent with a gradient **across the lane**: **25% transparent at the lane center, 75% at the lane edges** (both adjustable). The gradient is computed in each note's own lane coordinates, so it follows the note's perspective and taper — it is never screen-aligned.
  - **Keyboard proportions (grand piano):** white key 23.5 mm wide × 150 mm visible length; black key 13.7 mm × 95 mm, slightly raised. World unit = one white-key width. Key proportions are fixed in world space and never change with camera settings.
  - **Camera:** tilt default **45°** (adjustable); **distance offset**: 0 = all 88 keys exactly fill the screen width, positive = farther away, **negative = closer, cropping the outer keys**; **horizontal pan**, default centered. The keyboard and the highway share the camera, so lanes always meet their keys.
  - **Scene defaults (all adjustable):** background very dark blue (`#05070F`), highway surface slightly lighter (`#0A0F1E`); lane lines desaturated blue, translucent; bar lines the same hue, clearly more visible; beat lines barely visible; pedal band subtle desaturated blue-grey.
  - **Settings** are stored in localStorage (versioned) until profiles arrive in milestone 5.
  - **Player is the home page** (`/`); the debug page stays at `#/debug`.
  - **HUD:** top-left — song title, length, position (m:ss), bar:beat. Top-right — current BPM (song tempo at the position × tempo %), song BPM at the position, tempo %. Top-center — temporary controls (to be redesigned later). A gear button opens the settings panel.

## Pure logic (unit-tested in Node)

Put these where CLAUDE.md's rules fit best (pure, no Three.js imports):

1. **Key layout:** for MIDI 21–108 → `{ midi, isBlack, x, width, length, raised }` in world units, from the grand-piano proportions. Black keys centered on the boundary between their neighboring white keys. Tests: 88 keys, 52 white, 36 black, total width 52, A0 at the left edge, C8 at the right, black/white width and length ratios.
2. **Note instances:** from the hand-assigned notes → per-note render data `{ x, width, isBlack, startTick, endTick, headEndTick, colorIndex, hand }`. Unassigned channels excluded. Tests on the fixtures.
3. **Key states:** given notes and the current tick → per key `{ colorIndex, alpha }`: `1` while sounding; during the fade window before an onset (default 1 beat = ppq ticks, adjustable) alpha rises from 0 to a maximum approach alpha (default 0.7); otherwise 0. A sounding note beats an approaching one. Tests incl. repeated notes on one key and chords.
4. **Camera fit:** given tilt, vertical FOV, viewport aspect, distance offset and pan → camera position and look-at target such that, at offset 0 and pan 0, the keyboard's front edge spans the viewport width (within ±1%). Negative offsets move closer; the highway's far end and the keyboard front stay framed vertically. Tests for several tilts and aspects.
5. **Settings model:** typed settings with defaults, a schema version, and a `load(raw)` that merges stored values over defaults, clamps out-of-range numbers, and ignores unknown keys. Tests.

## Engine (`src/engine/`)

- An `Engine` class with an imperative API (no Vue reactivity around Three.js objects): `mount(canvas)`, `setSong(...)`, `applySettings(...)`, `resize()`, `dispose()`. It reads the transport's song position every animation frame (`positionAt(clock.now())`), never drives timing. Rendering pauses while the tab is hidden (audio keeps going, as in m2).
- **Notes:** one `InstancedMesh` of flat quads with a small custom shader. Per-instance attributes carry x, width, startTick, endTick, headEndTick, color; a uniform carries the current tick. The **shader** computes z from ticks, the head vs sustain split, the cross-lane gradient (from the quad's local u coordinate), and the horizon haze — so per frame the CPU updates only uniforms. Black-key notes render above white-key notes.
- **Highway:** surface, lane lines, bar lines and beat lines (from the bar map, so meter overrides apply), now line. Bar/beat lines scroll with the music and fade with the haze.
- **Pedal bands:** full-width quads per pedal interval of assigned channels (merged where they overlap), drawn under notes, same tick→z mapping.
- **Keyboard:** 88 key meshes at true proportions (black keys raised), white/black at rest; a color overlay per key driven by the key-state logic each frame.
- **Now-line effects:** onset burst (short spray of sparks) and a held glow (gentle pulse) in the pitch color, additive-blended sprites or instanced particles from a fixed pool (cap the count). No full-screen bloom.
- Pixel ratio capped at 2. Dispose geometries, materials and textures on song change and unmount.

## Player screen (`/`)

- Full-window canvas with the HUD layout from step 0.
- Temporary top-center controls: song picker (the three fixtures), play/pause, stop, prev/next bar, tempo slider, loop start/end bars, pre-roll beats. Keyboard shortcuts: Space = play/pause, ← / → = previous/next bar.
- Uses the m2 audio stack (samples load with progress; Play disabled until ready; audio unlock on first gesture).
- **Settings panel** (gear): camera tilt, distance offset, pan; look-ahead beats; key fade-in beats and max approach alpha; sustain center/edge transparency; background, highway, lane, bar, beat and pedal colors + opacities; effects on/off; "Reset to defaults". Changes apply live and persist to localStorage.
